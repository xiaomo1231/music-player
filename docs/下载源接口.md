# 下载源接口开发说明

“下载源”是自动获取里预留的一个接入点：把一个**能按关键字搜索、能给出下载地址**的服务接进播放器。接进来以后，它和订阅链接、网盘目录这些来源一样：

- 出现在“自动获取 → 我的来源 → 可添加的下载源”里，用户点一下就添加；
- 搜索结果进同一个搜索页，可以多选、AI 挑选、订阅追更；
- 下载走同一个队列（同时下载数、暂停 / 继续 / 取消 / 重试、限速、断点续传）；
- 下完自动补标签、保存歌词，再按 `音乐\艺人\专辑 (年份)\03 - 曲名.ext` 整理入库。

软件本身**不带任何下载源**（`builtin()` 是空的），界面上也不会出现这一栏，直到你接入第一个。

> 只接你有权获取内容的服务：官方开放接口、自己的网盘或 NAS、已购买可下载的曲目、CC 授权曲库等。不接绕过付费、会员、口令或其他访问限制的来源。

---

## 1. 整体流程

```
用户在搜索页输入关键字
  └─ fetch_search ──> provider::search ──> Provider::search(query, media_kind, page)
                                            返回 Vec<Item>
                     Item ──> Hit（kind = "provider"，url = provider://<id>/item?q=<档位>&d=<Item JSON>）
用户点“下载”
  └─ fetch_download ──> fetch_tasks 新增一行（kind = "provider"）
下载队列开始 / 继续这个任务
  └─ download::provider_download
        ├─ Provider::resolve(item, quality) ──> Resolved { target, lyric }
        ├─ Target::Http  ──> http_download（断点续传、重试 3 次、限速）
        │  Target::Ytdlp ──> ytdlp_download
        ├─ 音乐文件缺标签时用 Item 补上（标题 / 艺人 / 专辑 / 曲号）
        ├─ lyric 存成同名 .lrc
        └─ organize::finish ──> 改名、移入整理目录、入库、发 library://changed
```

要点：

- **`resolve` 在每次开始或继续下载时都会调用**。直链有时效也没关系，暂停一天再继续会重新取。
- 任务地址里带着完整的 `Item`（JSON），所以程序重启后继续下载也能 `resolve`。签名、会话令牌这类东西放进 `Item.extra` 就行。
- `.lrc` 和封面、字幕一样，整理时跟着同名音乐文件一起移动。播放器的歌词模块会读同名 `.lrc`。

## 2. 接口定义

全部在 `src-tauri/src/fetch/provider.rs`。

```rust
pub trait Provider: Send + Sync {
    fn info(&self) -> ProviderInfo;
    fn search<'a>(&'a self, query: &'a str, media_kind: &'a str, page: u32)
        -> BoxFuture<'a, Result<Vec<Item>, String>>;
    fn resolve<'a>(&'a self, item: &'a Item, quality: &'a str)
        -> BoxFuture<'a, Result<Resolved, String>>;
}
```

`BoxFuture` 来自 `futures_util::future::BoxFuture`。实现时写成 `Box::pin(async move { ... })`。错误直接返回给用户看的中文句子，例如 `Err("需要先在设置里填写 API 密钥".into())`。

### ProviderInfo

| 字段 | 说明 |
| --- | --- |
| `id` | 唯一标识，只用小写字母、数字和 `-`。保存在来源表里（`provider://<id>`），**发布后不要改** |
| `name` | 显示名 |
| `media_kinds` | 支持的类型：`music` / `video` / `anime`。搜索页选了别的类型时不会调用 `search`。留空表示都支持 |
| `note` | 一句话说明，鼠标悬停在“添加”按钮上时显示 |

### Item（搜索结果）

| 字段 | 说明 |
| --- | --- |
| `id` | 下载源内部 id |
| `title` / `artist` / `album` | 曲名、艺人、专辑。整理入库靠艺人归档，**音乐一定要给艺人** |
| `year` / `track` | 年份、曲号，可选 |
| `duration` | 秒，可选 |
| `cover` | 封面网址，可选（目前搜索页不显示） |
| `media_kind` | `music` / `video` / `anime` |
| `qualities` | 可选档位，**从好到差排**。第一项是默认档位，搜索页显示它的 `label` 和 `size` |
| `extra` | 下载源自用数据，原样带回 `resolve` |

`Quality`：`key`（传回 `resolve` 的档位标识）、`label`（“无损”“320K”“1080P”）、`format`、`bitrate`（kbps，可选）、`size`（字节，可选）。

### Resolved（下载地址）

```rust
pub enum Target {
    Http { url: String, ext: String },   // 直链；ext 是扩展名，不带点
    Ytdlp { url: String },               // 交给 yt-dlp 的页面地址
}
pub struct Resolved { pub target: Target, pub lyric: Option<String> }
```

- `Http`：下载到 `下载目录\歌名 - 艺人.ext`。
- `Ytdlp`：下载到 `下载目录\yt-<任务号>\`，文件名由 yt-dlp 决定。
- `lyric`：LRC 全文，没有就给 `None`。

## 3. 接入一个新下载源

1. 新建 `src-tauri/src/fetch/<名字>.rs`，实现 `Provider`。
2. 在 `src-tauri/src/fetch.rs` 顶部加 `pub mod <名字>;`。
3. 在 `provider.rs` 的 `builtin()` 里加一行：

   ```rust
   fn builtin() -> Vec<Arc<dyn Provider>> {
       vec![Arc::new(super::<名字>::<结构体>::default())]
   }
   ```

4. 写单元测试（见第 6 节），跑 `cargo test --lib fetch`、`cargo check --lib`。

不需要改前端、数据库表或命令注册。

### 示例骨架

下面是一个基于 JSON 开放接口的示例。网址和字段名是假设的，接真实服务时按它的文档改。

```rust
//! 示例开放曲库（CC 授权）
use super::provider::{Item, Provider, ProviderInfo, Quality, Resolved, Target};
use super::source;
use futures_util::future::BoxFuture;
use serde_json::Value;

#[derive(Default)]
pub struct OpenLib;

const API: &str = "https://api.example.org/v1";

impl Provider for OpenLib {
    fn info(&self) -> ProviderInfo {
        ProviderInfo {
            id: "openlib".into(),
            name: "示例开放曲库".into(),
            media_kinds: vec!["music".into()],
            note: "CC 授权音乐，免费下载".into(),
        }
    }

    fn search<'a>(&'a self, query: &'a str, _mk: &'a str, page: u32) -> BoxFuture<'a, Result<Vec<Item>, String>> {
        Box::pin(async move {
            let url = format!("{API}/tracks?q={}&page={page}", urlencoding(query));
            source::throttle(&url).await;                         // 同一站点 1 秒一次
            let resp = source::client().get(&url).send().await.map_err(|e| format!("连接失败：{e}"))?;
            source::check_status(resp.status())?;                 // 401 / 403 直接报“需要登录”，不绕过
            let v: Value = resp.json().await.map_err(|e| format!("返回格式不对：{e}"))?;
            let list = v["results"].as_array().cloned().unwrap_or_default();
            Ok(list.iter().map(|t| Item {
                id: t["id"].as_str().unwrap_or_default().into(),
                title: t["name"].as_str().unwrap_or_default().into(),
                artist: t["artist"].as_str().unwrap_or_default().into(),
                album: t["album"].as_str().unwrap_or_default().into(),
                media_kind: "music".into(),
                qualities: vec![
                    Quality { key: "flac".into(), label: "无损".into(), format: "flac".into(), ..Default::default() },
                    Quality { key: "mp3".into(), label: "MP3".into(), format: "mp3".into(), bitrate: Some(320), ..Default::default() },
                ],
                extra: Value::Null,
                ..Default::default()
            }).collect())
        })
    }

    fn resolve<'a>(&'a self, item: &'a Item, quality: &'a str) -> BoxFuture<'a, Result<Resolved, String>> {
        Box::pin(async move {
            let fmt = if quality.is_empty() { "flac" } else { quality };
            Ok(Resolved {
                target: Target::Http { url: format!("{API}/tracks/{}/file?format={fmt}", item.id), ext: fmt.into() },
                lyric: None,
            })
        })
    }
}

fn urlencoding(s: &str) -> String {
    url::form_urlencoded::byte_serialize(s.as_bytes()).collect()
}
```

### 可以直接用的工具（`fetch/source.rs`）

| 函数 | 作用 |
| --- | --- |
| `source::client()` | 共用的 `reqwest::Client`（rustls，User-Agent `MediaPlayerFetch/1.0`） |
| `source::throttle(url).await` | 同一站点两次请求至少间隔 1 秒，**每次请求前都要调用** |
| `source::check_status(status)` | 401 / 403 返回“需要登录或验证码”的说明 |
| `source::http_bytes(url).await` | 带节流的 GET，返回字节 |
| `source::ytdlp_path()` | yt-dlp 路径（没有时为 `None`） |

## 4. 账号和密钥

需要 API 密钥或登录的下载源，把凭据存在设置表里，别写进代码：

```rust
// 读（返回 Option<serde_json::Value>）
let key = crate::library::get_setting(&conn, "provider.openlib.key")
    .ok()
    .flatten()
    .and_then(|v| v.as_str().map(String::from))
    .unwrap_or_default();
```

`with_db` 拿锁时不能跨 `await`：先在锁里把需要的值读出来，再发请求。设置界面目前没有给下载源留位置，需要时在 `FetchSettings.svelte` 里加一栏。

登录页、验证码一律让用户在浏览器里自己完成，下载源只使用用户给的凭据，不做自动登录或绕过。

## 5. 命令和数据

| 项 | 内容 |
| --- | --- |
| 命令 `fetch_providers` | 返回 `ProviderInfo[]`，前端用它显示“可添加的下载源” |
| 添加来源 | `fetch_add_source(kind = "provider", url = "provider://<id>", name)`；id 不存在时报错 |
| 来源表 | `fetch_sources.kind = "provider"`，`url = provider://<id>` |
| 任务表 | `fetch_tasks.kind = "provider"`，`url = provider://<id>/item?q=<档位>&d=<Item JSON>` |
| 搜索结果 `Hit` | `kind = "provider"`，`title = 曲名 - 艺人 [档位]`，`work = 专辑`（没有专辑用曲名），`group = 艺人`，`resolution = 档位文字` |

用户删掉某个下载源的代码后，已添加的来源搜索时会提示“这个版本的软件里没有下载源 …”，不会崩溃。

## 6. 测试

`provider.rs` 里有一个不联网的假下载源 `tests::Mock`，可以照着写：

- 解析测试：把一段真实接口返回的 JSON 放进测试里，检查转换出的 `Item`（尤其是艺人、档位顺序）。
- 不要在单元测试里访问网络。
- 真机测试用独立数据目录（`MP_DATA_DIR`、`WEBVIEW2_USER_DATA_FOLDER`，见 `开发约定.md`），先下一首，确认标签、歌词和整理后的路径都对。

已有测试（`cargo test --lib provider`）：任务地址往返、id 解析、文件名、`Hit` 转换、注册表和假下载源完整流程、歌词保存、缺标签时补标签。

## 7. 现在没做的

- 搜索只取第 1 页（`page` 参数已留好，界面没有翻页）。
- 搜索页没有档位选择，下载默认档位（`qualities` 第一项）。
- 不显示封面，`Item.cover` 暂未使用。
- `Target::Http` 不能附带自定义请求头（Referer、Cookie 等）。需要时给 `Target::Http` 加 `headers` 字段，在 `download.rs` 的 `http_download` 里带上。
- 只支持编译进软件的下载源，没有外部插件（脚本 / DLL）加载。
