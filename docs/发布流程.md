# 发布流程与自动更新

## 用户这边看到的

- 软件启动 5 秒后去 GitHub 看有没有新版本（“设置 → 关于 → 启动时自动检查更新”可以关掉），也可以在“设置 → 关于”里点“检查更新”。
- 有新版本时弹窗，显示版本号和更新说明，三个按钮：
  - **立即更新**：下载安装包，校验签名后覆盖安装，程序自动关闭再重新打开。媒体库和设置不受影响。
  - **以后再说**：这次不更新，下次启动还会提示。
  - **跳过这个版本**：这个版本不再自动弹窗（手动检查仍会显示），出了更新的版本会再提示。
- 不会静默下载或安装。

## 原理

- 用 Tauri 官方 updater 插件。软件读取 `https://github.com/xiaomo1231/music-player/releases/latest/download/latest.json`，也就是**最新一个正式 Release**（草稿和预发布不算）里的 `latest.json`。
- 安装包用私钥签名，软件里内置公钥（`src-tauri/tauri.conf.json` 的 `plugins.updater.pubkey`），签名对不上就拒绝安装。所以别人就算往 Release 里放了别的安装包也装不进来。

## 签名密钥（重要）

- 私钥：`%USERPROFILE%\.tauri\music-player-updater.key`
- 私钥密码：`%USERPROFILE%\.tauri\music-player-updater.password.txt`
- 公钥：同目录 `music-player-updater.key.pub`（已经写进 `tauri.conf.json`）

私钥和密码**不能提交到仓库，也不要发给别人**。请把这两个文件另外备份一份（U 盘或密码管理器）。
**丢了就再也发不出能被旧版本接受的更新**，只能换新密钥，所有用户手动重装一次。

GitHub Actions 发布要用的仓库 Secrets（在仓库 Settings → Secrets and variables → Actions 里添加，或者用下面的命令）：

```powershell
Get-Content "$env:USERPROFILE\.tauri\music-player-updater.key" -Raw | gh secret set TAURI_SIGNING_PRIVATE_KEY --repo xiaomo1231/music-player
Get-Content "$env:USERPROFILE\.tauri\music-player-updater.password.txt" -Raw | gh secret set TAURI_SIGNING_PRIVATE_KEY_PASSWORD --repo xiaomo1231/music-player
```

## 版本号规范

用 `主.次.修订`（语义化版本），标签前面加 `v`：

| 改了什么 | 怎么升 | 例子 |
| --- | --- | --- |
| 只修 bug、小调整 | 修订号 +1 | 0.2.0 → 0.2.1 |
| 加了新功能 | 次版本号 +1，修订号归零 | 0.2.1 → 0.3.0 |
| 数据格式不兼容、大改版 | 主版本号 +1 | 0.9.0 → 1.0.0 |

版本号写在 4 个地方（`package.json`、`src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml`、`src-tauri/Cargo.lock`），用脚本一起改，不要手改：

```powershell
powershell -ExecutionPolicy Bypass -File tools/bump-version.ps1 0.2.1
```

只有准备发布时才改版本号，平时开发的 PR 不动它。

## 发一个新版本

1. 从最新的 `main` 开一个分支，运行 `tools/bump-version.ps1 <新版本号>`。
2. 在 `CHANGELOG.md` 最上面加一节 `## <新版本号>`，用用户能看懂的话写更新内容（会显示在更新弹窗里）。
3. 开 PR，CI 通过后合并到 `main`。
4. 切回 `main` 并拉取最新代码，然后二选一：
   - **GitHub Actions 打包**（需要已经设好 Secrets，Actions 有额度）：

     ```powershell
     git tag v0.2.1
     git push origin v0.2.1
     ```

     或者在 GitHub 的 Actions → Release 页面点 “Run workflow”。
   - **本机打包上传**（Actions 跑不了时用这个；需要本机有私钥和登录过的 `gh`）：

     ```powershell
     powershell -ExecutionPolicy Bypass -File tools/release.ps1
     ```

   两种方式跑的是同一个脚本 `tools/release.ps1`：打 NSIS 安装包并签名，生成 `latest.json`，创建 Release `v<版本号>` 并上传安装包、签名和 `latest.json`。只想先在本机看看安装包，加 `-DryRun`（输出在 `release-out/`，不上传）。
5. 发布后打开一个旧版本，到“设置 → 关于”点“检查更新”确认能看到新版本。

## 出问题时

- **发错了**：在 GitHub 上删掉这个 Release 和标签（`gh release delete v0.2.1 --cleanup-tag`），旧版本就会回到上一个 Release。已经更新到错误版本的用户，需要再发一个更高版本号的修复版。
- **检查更新报错**：确认最新 Release 里有 `latest.json`，并且不是草稿 / 预发布。
- **签名错误**：打包时用的私钥和 `tauri.conf.json` 里的公钥不是一对。
