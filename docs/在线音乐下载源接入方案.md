# 在线音乐（flac.music.hi.cn）接入方案

> 目标：把 flac.music.hi.cn 的搜索 / 解析 / 歌词接成你框架里的一个 `Provider`，
> 复用现有的搜索页、下载队列、断点续传、补标签、存歌词、整理入库，**不改前端、不改数据库**。
>
> 结论：能直接接，改动是 **1 个新文件 + 2 行注册**。下面给出可直接编译的实现
> （`src-tauri/src/fetch/onlinemusic.rs`）和验证步骤。

---

## 1. 为什么能"零改动"接进来

你的 `Provider` 契约要三样东西：能按关键字搜、能给每首歌多个档位、能在下载前把
"(曲目 + 档位)" 换成直链。在线音乐的接口正好是这三样：

| 框架需要 | 在线音乐接口 | 说明 |
| --- | --- | --- |
| `search(query, media_kind, page)` | `POST /ajax.php?act=search` | `platform` + `keyword` + `page` + `size` |
| `Item.qualities` | 响应里的 `minfo[]` | 每项一个 `format` / `bitrate` / `size` |
| `resolve(item, quality)` → `Target::Http` | `POST /ajax.php?act=getUrl` | 回 `data.url` 直链 |
| `Resolved.lyric` | `POST /ajax.php?act=getLyric` | 回 LRC 全文 |
| `Item.artist` / `album` / `cover` / `duration` | `artist` / `album_name` / `pic_url` / `duration` | 整理入库、补标签都用得上 |

协议细节（逆向自站点 bundle 的 `Xb()`）：

```text
POST {BASE}/ajax.php?act=search    body: platform=kuwo|wyy & keyword & page & size
     -> {"code":0,"data":{"total":3514,"list":[{
          "id":"394586518","name":"青花瓷","artist":"周杰伦","album_name":"我很忙",
          "pic_url":"https://…","duration":"208",
          "minfo":[{"level":"ff","bitrate":"2000","format":"flac","size":"57.26Mb"}, …],
          "time":1795379858,"sign":"1b48061220b0747abd3891a4a8122014"}]}}

POST {BASE}/ajax.php?act=getUrl    body: platform & songid & format & bitrate & time & sign
     -> {"code":0,"data":{"url":"https://other-er.kuwo.cn/…/x.mp3","format":"mp3","bitrate":128}}

POST {BASE}/ajax.php?act=getLyric  body: platform & songid & time & sign
     -> {"code":0,"data":"[00:00.00]…"}
```

**两个必须记住的点**：

1. `act` 在 query 上，**其余参数全在 form body 里**（PHP 只从 `$_POST` 读）。
   把 `keyword` 拼进 query 会得到"搜索关键词不能为空"——不是反爬，是取参方式。
2. `time` / `sign` 是搜索接口按"会话 + 单曲"签发的，必须**原样回传**。它们不能自己算，
   也不需要算——跟着 `Item` 一起进 `extra` 就行，正好满足你文档里"`resolve` 每次开始 /
   继续下载都重新调用"的约定：暂停一天再继续，依然用 `extra` 里那份，过期了就地重签
   （见第 5 节）。

## 2. 数据映射

### 2.1 搜索结果 → `Item`

| `Item` 字段 | 来源 | 备注 |
| --- | --- | --- |
| `id` | `id` | 站点内部曲号，`getUrl` 的 `songid` |
| `title` | `name` | |
| `artist` | `artist` | 整理入库按艺人归档，必须给（站点一定有） |
| `album` | `album_name` | 搜索页按专辑分组、入库建文件夹都用它 |
| `duration` | `duration` | 站点的秒数字符串 → `f64` |
| `cover` | `pic_url` | 搜索页小图 |
| `media_kind` | 常量 `"music"` | |
| `qualities` | `minfo[]` | **要重排**，见 2.2 |
| `extra` | `{platform, songid, time, sign}` | `resolve` 的全部输入 |
| `series` / `season` / `episode` | 不填 | 音乐用不到；填了会被当成"集"触发追更 |

### 2.2 `minfo[]` → `Quality`（有一个方向性坑）

站点返回的 `minfo` 是**从低到高**（128K → 320K → FLAC），而你的框架约定
"从好到差排，第一项是默认档位"。所以转换时必须排序，否则默认档位会变成 128K MP3。
实现里用 `rank()` 排：FLAC 优先，其次按码率。

| `Quality` 字段 | 取值 | 示例 |
| --- | --- | --- |
| `key` | `格式:码率` | `flac:2000`、`mp3:320` |
| `label` | 无损 / 320K / 128K | FLAC → "无损" |
| `format` | `flac` / `mp3` | 直接当 `Target::Http.ext` |
| `bitrate` | 留空（`..Default::default()`） | 码率已经写进 `key`/`label`；该字段的整型宽度文档里没写，硬编会踩类型错 |
| `size` | `57.26Mb` → 字节 | 复用 `source::parse_size` |

`key` 里既带格式又带码率，是因为 `resolve` 要同时回传 `format` 和 `bitrate` 两个字段；
前端 `withQuality` 只改 `q`，不解析内容，所以 `key` 的格式对前端无感。

## 2.3 对外可见的标识（中性化）

下载源在界面上的身份都收成了软件自带来源的样子，不出现上游站点名：

| 位置 | 取值 | 说明 |
| --- | --- | --- |
| `ProviderInfo.id` | `onlinemusic` | 存进 `fetch_sources.url = provider://onlinemusic`，**发布后不能改**，否则用户已添加的来源会失效（会提示"这个版本里没有下载源"） |
| `ProviderInfo.name` | `在线音乐` | 出现在"可添加的下载源"列表和来源管理里 |
| `ProviderInfo.note` | `在线搜索并下载音乐，支持有损 MP3 与无损 FLAC，自动附带歌词。` | 悬停提示，不提站点、不提"公开接口" |
| 失败文案 | `连接音乐服务失败` / `音乐服务返回的内容无法解析` / `音乐服务暂时不可用` / `音乐服务拒绝了这次请求（403）` | 任务列表里只看到"音乐服务" |
| 模块 / 结构体 | `fetch/onlinemusic.rs` / `OnlineMusic` | 与 `ink.rs` / `reel.rs` 的命名风格一致 |

需要知道的两点：

- 这些是**本地标识**，一个字节都不会发给服务器；请求里能体现身份的只有 UA / Referer / 请求节奏 / IP。
- 下游直链里的域名（`other-er.kuwo.cn` 之类）是上游 CDN 给的，换不掉；如果界面上会显示下载地址，那里仍看得出真实来源。

## 4. 实现要点（为什么这么写）

### 4.1 POST + 手写 form body

`reqwest` 在 `default-features = false` 下，`.form()` 是否可用取决于版本特性开关。
为了不赌这个，用你已有的 `url` crate 自己编码，然后 `body(...)` + 显式
`Content-Type`——和你 `provider.rs` 里 `task_url` 的编码方式同一套，行为最稳。

### 4.2 音源切换：关键词前缀

搜索页没给下载源留设置项（你的文档第 4 节也提到这点），而站点有两个上游。
硬编码成酷我会浪费一半曲库，所以约定：

| 输入 | 走哪个上游 |
| --- | --- |
| `青花瓷` | 酷我（默认） |
| `wyy:青花瓷` / `网易:青花瓷` | 网易云 |
| `kuwo:青花瓷` / `酷我:青花瓷` | 酷我（显式指定） |

前缀只影响 `search`，解析时用的是 `Item.extra.platform`，同一批结果混着也没问题。
`note` 里已经写明这个用法，鼠标悬停就能看到。要改默认音源，只改 `split_platform`
最后一行。

### 4.3 一次 `resolve` 打两个接口

`resolve` 先 `getUrl` 拿直链，再尽力 `getLyric` 拿歌词。歌词失败**不影响下载**
（返回 `lyric: None`），避免因为某首没歌词就整首失败。歌词拿回来后由框架
`provider::save_lyric` 存成同名 `.lrc`，整理入库时跟着音乐文件走。

### 4.4 签名过期自愈

`extra` 里的 `time/sign` 可能过期（站点按会话签发）。发生错误时按 `title` 重搜一次，
找到同一个 `id` 就把新的 `time/sign` 塞回去重试一次；再失败才把原始错误抛给用户。
这样"暂停很久 → 继续下载"不会直接失败。

### 4.5 为什么不填 `Quality.bitrate`

`key` 已经是 `格式:码率`，`label` 也带了 `320K/128K`，下拉框显示的信息够了。
而 `Quality.bitrate` 的整数类型（`u32` 还是 `i64`）在 `下载源接口.md` 里没标注，
硬编 `Some(320)` 万一类型不符就编译不过。所以用 `..Default::default()` 留空，
码率统一从 `key` 里解析；要填的话，按字段实际类型加一行 `bitrate: Some(b as _)` 即可。

### 4.6 档位兜底

个别结果没有 `minfo`（站点偶尔如此）。这时塞一个 `mp3` 档位，`bitrate` 留空让站点给默认，
至少还能试一次，而不是让这首在搜索列表里看起来"没有可下载档位"。

## 5. 已知边界（都是站点侧的，不是实现问题）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 每页只有 10~15 条，`size=50` 也一样 | 上游搜索源的分页粒度，`size` 不严格生效 | 已按 20 传；要更多就翻 `page`。界面目前不翻页，够用 |
| 搜索页搜不到本来源的结果 | 搜索页的**类型**没选「音乐」：框架在 `fetch_search` 里把空类型当成 `anime`，而本来源只声明 `media_kinds=["music"]`，会被直接过滤 | 使用前把类型切到「音乐」；代码里也做了同一层兜底（非 music 直接返回空） |
| 用艺人名搜不到 | 站点只拿 `keyword` 当歌名查 | 已在 `note`/错误里提示"用歌名" |
| `size=1` 返回空 `list` | 站点侧的 off-by-one | 实现里固定 `size=20`，不会踩到 |
| 直链是 CDN 临时地址 | 带签名的短期 URL | `resolve` 每次重新取，天然正确 |
| 站点前端有"口令"弹窗 | 前端 `localStorage` 点击计数，第 6 次才拦一下 | **本实现完全不碰它**：只调 `ajax.php` 的搜索/解析，不请求 `kl.php`、不写 `localStorage`、不做任何绕过逻辑 |

如果哪天 `getUrl` 开始要求额外条件，错误会以站点原文（中文）显示在任务里，
不会静默失败。

### 6.2 真机

1. 独立数据目录启动：`MP_DATA_DIR`、`WEBVIEW2_USER_DATA_FOLDER`（见 `开发约定.md`）。
2. 自动获取 → 我的来源 → 添加下载源 → 看到 **在线音乐** → 添加。
3. 搜索页把**类型切到「音乐」**（不切的话框架会按 `anime` 过滤掉本来源），再搜 `青花瓷`，确认：封面、`周杰伦`、`我很忙`、档位下拉里是 `无损 / 320K / 128K`。
4. 选 `无损` 下载，确认：`下载目录\青花瓷 - 周杰伦.flac`、同名 `.lrc` 存在、
   整理后落到 `音乐\周杰伦\我很忙\03 - 青花瓷.flac`（曲号没有就按框架默认）。
5. 暂停 → 等一会儿 → 继续，确认能续传（`resolve` 重新取直链）。
6. 搜 `wyy:青花瓷`，确认结果换成网易云那批（`id` 是纯数字，封面域名不同）。

## 7. 分阶段落地

| 阶段 | 内容 | 状态 |
| --- | --- | --- |
| P0 | 搜索 + 直链 + 歌词（本文档 + `onlinemusic.rs`） | 已完成，可直接编译 |
| P1 | 若 CDN 以后要求 `Referer`：给 `Target::Http` 加 `headers`（你文档第 8 节预留的位置），`download.rs` 的 `http_download` 带上 | 需要时再做 |
| P2 | 设置项：在 `FetchSettings` 加 `onlinemusic_platform`，`FetchSettings.svelte` 加一栏，替代关键词前缀 | 可选 |
| P3 | 专辑 / 歌单接入：站点还有 `act=album` / `act=playlist`，可以做成"粘贴专辑链接 → 整张下载" | 可选 |

P3 说明：`act=album` 传 `platform` + `id`，`act=playlist` 传 `platform` + `id` + `page` + `size`，
返回结构和 `search` 一样（`list` + `total`，另带 `info` 封面/简介）。接法是给
`onlinemusic.rs` 加一个"从链接解析出 id"的分支，在 `search` 里识别 `kuwo.cn/album_detail/…`、
`music.163.com/#/album?id=…` 这类输入。

## 8. 回滚

删掉 `onlinemusic.rs`、去掉 `fetch.rs` 的 `pub mod onlinemusic;`、把 `builtin()` 改回单个元素即可。
已经添加的来源会在搜索时提示"这个版本的软件里没有下载源 onlinemusic"——你文档第 6 节
已经保证"不会崩溃"，用户删来源即可。

## 9. 一句合规说明

站点页脚自己写明资源来自第三方搜索引擎、仅供试听、版权归原方；这个接入只做
"搜索 + 解析公开接口 + 下载"，不处理站点的口令页、不做任何访问控制绕过。
如果要对外分发，建议在 `note` 里保留"仅解析公开接口"的措辞，并把是否启用放在用户侧。
