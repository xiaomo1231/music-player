## Rust 侧规则

- 每个功能一个模块文件（已建好空壳：`media.rs adclean.rs convert.rs subtitle.rs organize.rs daily.rs fetch.rs mangatr.rs shell.rs`）。
  - `pub fn init(conn)`：启动时建自己的表，用 `CREATE TABLE IF NOT EXISTS`。
  - `pub fn setup(app)`：启动时调用一次。
- 命令写成 `#[tauri::command] pub fn xxx(...) -> Result<T, String>`（或 async）。名字加模块前缀，例如 `convert_add`、`media_thumb`。
- 拿状态：`st: tauri::State<crate::AppState>`；`st.db.lock()` 是 `rusqlite::Connection`（parking_lot 锁，别跨 await 持有）；`st.dirs.covers / thumbs / data`。
- 长任务放线程或 `tauri::async_runtime::spawn`，进度用 `app.emit("模块://事件", payload)` 推给前端。
- 不要改 `lib.rs`、`Cargo.toml`、`db.rs`。需要注册的命令、要加的依赖，写进 `docs/integration/<模块>.md`（见下）。
- 自测：`cargo test --lib`、`cargo check`（在 `src-tauri` 目录）。每个模块至少写几个单元测试（纯函数部分）。

## 前端规则

- 只改自己负责的 `views/`、`overlays/` 文件，新组件放 `src/components/<模块名>/`，新的前端逻辑放 `src/lib/<模块名>.ts` 或 `.svelte.ts`（自己的类型也定义在这里，不要改 api.ts）。
- 调后端：`import { invoke, listen, inTauri, fileUrl, coverUrl } from '../lib/api'`。浏览器里直接打开（`inTauri` 为 false）时不要报错，显示空状态即可。
- 提示用 `toast('…')`；弹窗用 `<Modal>`；图标用 `<Icon name=…>`。
- 本地文件给 `<video>` / `<img>` 用 `fileUrl(路径)`（Tauri 的 asset 协议，支持拖动进度）。
- 文案用简体中文，口吻简洁；不显示演示用的假数据。
- 自测：项目根目录 `pnpm check`（类型检查）、`pnpm build`。

## 集成说明文件

每个模块在 `docs/integration/<模块>.md` 里写清楚：

1. 要在 `lib.rs` 的 `generate_handler!` 里注册的命令（完整路径，如 `convert::convert_add`）
2. 需要的新依赖（Cargo / npm）和 Tauri 权限
3. 需要 `ui.svelte.ts` / `api.ts` / `App.svelte` 增加的东西
4. 已做的自测和已知问题
