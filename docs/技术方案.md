# 综合媒体播放器 · 技术方案

> 平台：Windows 10 / 11　｜　框架：Tauri 2 + Rust　｜　数据：纯本地，不做同步
> 配套的界面原型在 `demos/` 目录，双击 `demos/index.html` 即可查看。默认界面定为“极光玻璃”，升级版原型是 `demos/11-aurora-pro.html`。
> 第 11 至 16 节是第二轮新增的功能：番剧与漫画、音乐库分组、转换回写、AI 字幕、漫画翻译、自动获取与归类。

## 1. 目标与范围

一个软件管好并播放电脑里的五类内容：**音乐、视频、番剧、漫画、小说**，外加内置的**格式转换**和一组可选的 **AI 工具**（字幕生成、漫画翻译、自动获取）。

| 需求 | 结论 |
| --- | --- |
| 平台 | 只做 Windows |
| 技术栈 | Tauri 2（Rust 后端 + WebView2 前端） |
| 小说 / 动漫 | 本地 TXT / EPUB 阅读器；本地番剧库，按番剧、季、集整理，不做在线源 |
| 元数据联网补全 | 做，默认关闭，由用户开关；关闭时完全离线 |
| 加密格式（qmc / mgg / mflac 等） | 做成可选插件，默认不带，仅用于用户本人已购内容 |
| 扫描 | 首次启动向导，可选全盘或指定盘 / 文件夹；实时监控可开关 |
| 播放功能 | 均衡器、独占输出、字幕、倍速、硬件解码、播放列表、迷你播放器全部要 |
| 界面 | 简约有风格、有动效，能长期挂在桌面当背景，带 OLED 防烧屏 |

暂不做：多设备同步、局域网串流、手机端。软件本身不内置、不提供任何内容来源（见第 16 节）。

## 2. 总体架构

```
┌──────────────────────── 前端（WebView2）────────────────────────┐
│  界面 · 主题皮肤 · 歌词 / 可视化动效 · 阅读器 · 设置             │
└───────────────▲──────────────────────────────▲─────────────────┘
        Tauri 命令（请求 / 响应）        Tauri 事件（进度、播放状态、频谱）
┌───────────────┴──────────────────────────────┴─────────────────┐
│                       Rust 核心（src-tauri）                     │
│  player   播放引擎（libmpv）      library  媒体库（SQLite）      │
│  scanner  扫描与文件监控          metadata 标签读取 / 联网补全   │
│  convert  转换队列（FFmpeg）      reader   小说解析             │
│  plugins  插件宿主（加密格式等）  shell    窗口 / 托盘 / 壁纸模式 │
└────────────────────────────────────────────────────────────────┘
        libmpv（内含 FFmpeg 解码器）     ffmpeg.exe（转换用）
```

前端只负责显示和交互，所有读盘、解码、转换都在 Rust 侧完成，界面不会因为扫描或转码而卡顿。

### 技术选型

| 部分 | 选择 | 理由 |
| --- | --- | --- |
| 应用框架 | Tauri 2 | 安装包小（十几 MB 起，不含解码库），内存占用远低于 Electron |
| 前端 | TypeScript + Svelte 5（或 SolidJS）+ Vite | 运行时小、动画性能好；10 款 demo 的 CSS 和动效可以直接搬进来 |
| 播放引擎 | **libmpv**（`libmpv2` crate） | 一套引擎同时解决音频和视频，格式覆盖最广，见第 3 节 |
| 数据库 | SQLite（`rusqlite`，开启 FTS5 全文搜索） | 单文件、零配置，几十万条记录也够快 |
| 标签读取 | `lofty`（音频标签）+ mpv / ffprobe（视频信息） | 覆盖 ID3、Vorbis、APE、MP4 等主流标签 |
| 文件监控 | `notify`（底层是 ReadDirectoryChangesW） | 实时发现新增、移动、删除 |
| 转换 | 随包附带的 `ffmpeg.exe` | 见第 5 节 |
| 小说 | `encoding_rs` + `chardetng`（编码识别）、`epub` crate | GBK / UTF-8 / Big5 自动识别 |

## 3. 播放与解码：如何做到 90% 以上格式

核心思路是**不自己写解码器**，直接嵌入 libmpv。mpv 内部使用 FFmpeg，是目前格式支持最全的开源播放内核，常见播放器里大多数“什么都能播”的产品都基于同一套东西。

**覆盖范围（开箱即用）**

- 音频：MP3、AAC / M4A、FLAC、ALAC、WAV、APE、WavPack、OGG Vorbis、Opus、WMA、AIFF、DSD（DSF / DFF）、TTA、TAK、AC3、DTS，以及 CUE 整轨分轨
- 视频封装：MP4、MKV、AVI、MOV、WMV、FLV、WebM、TS / M2TS、RMVB、3GP
- 视频编码：H.264、H.265 / HEVC（含 10bit）、AV1、VP8 / VP9、MPEG-2 / 4、VC-1、RealVideo
- 字幕：SRT、ASS / SSA（libass 完整特效）、PGS、VobSub，内嵌与外挂均可

**进阶功能对应的实现**

| 功能 | 实现方式 |
| --- | --- |
| 硬件解码 | mpv `hwdec=d3d11va`，失败自动回退软解 |
| WASAPI 独占 / 比特完美 | mpv `audio-exclusive=yes`，按文件采样率输出 |
| 10 段均衡器 | mpv 音频滤镜链（FFmpeg `equalizer` / `firequalizer`） |
| 倍速不变调 | mpv `scaletempo2` |
| 无缝播放、ReplayGain | mpv `gapless-audio`、`replaygain` 选项 |
| HDR | mpv `gpu-next` 渲染器的色调映射 |
| 频谱 / 波形动效 | Rust 侧取 PCM 做 FFT，以每秒 30–60 次的事件推给前端 |
| 歌词 | 读取内嵌歌词和同名 `.lrc`，支持逐行与逐字（增强 LRC） |

**视频画面怎么放进 Tauri 窗口**：创建一个子窗口交给 mpv 渲染（`--wid`），放在透明的 WebView 下方，控制栏、字幕选择等界面浮在上面。这是 Tauri + mpv 的常见做法，也是整个项目里技术风险最高的一点，所以排在路线图最前面先验证。

## 4. 扫描与媒体库

**首次扫描流程**

1. 向导里选“全盘”或指定磁盘 / 文件夹，确认排除目录（默认跳过 `Windows`、`Program Files`、游戏目录、`node_modules`、回收站）。
2. **快速枚举**：多线程遍历目录（`jwalk`），先只按扩展名筛选，不打开文件。百万级文件通常在几十秒到几分钟内完成，取决于硬盘类型。
3. **分类**：按扩展名和所在路径分成音乐 / 视频 / 动漫 / 小说。
4. **读取信息**：后台线程池读标签、时长、分辨率，生成封面缩略图，写入 SQLite。界面在这一步就能陆续看到内容。
5. **可选联网补全**：仅在用户开启时进行。

**可选加速**：NTFS 分区可以直接读主文件表（MFT）来枚举，速度快一个数量级，但需要管理员权限，所以做成设置里的可选项而不是默认行为。

**增量与实时监控**

- 每个文件记录路径、大小、修改时间；再次扫描时只处理有变化的。
- 开启“实时监控”后，用 `notify` 监听已添加的文件夹，新下载的文件几秒内自动入库。
- 文件被移动时按大小 + 修改时间 + 内容指纹匹配，保留播放次数、进度和收藏。

**动漫识别**：解析文件名里的字幕组、番剧名、季、集、分辨率（如 `[字幕组] 番剧名 S02 - 07 [1080p].mkv`），同一番剧自动归到一起，并记录每一部看到第几集。电影和剧集走同样的规则。

**元数据联网补全（用户开关，默认关）**

| 类型 | 数据源 |
| --- | --- |
| 音乐标签、封面 | MusicBrainz + Cover Art Archive |
| 歌词 | LRCLIB 等开放歌词库 |
| 电影、剧集 | TMDB（需要申请 API Key） |
| 动漫 | Bangumi |

只发送查询所需的标题 / 艺人等关键字，不上传文件；下载结果缓存在本地。

## 5. 格式转换

- 随安装包附带 `ffmpeg.exe`，由 Rust 管理一个任务队列，通过 `-progress` 输出实时进度，可暂停、取消、限制并发数。
- 预设：转 MP3 / FLAC / AAC / Opus、转 MP4（H.264 / H.265）、仅换封装（不重编码，秒级完成）、提取音轨、视频转 GIF、压制字幕、响度均衡。
- 有独显或核显时自动使用 NVENC / QSV / AMF 硬件编码。
- 转换后可选保留原标签和封面，并自动加入媒体库。

**许可证提示**：FFmpeg 若包含 x264 / x265 则属于 GPL，会影响本软件的发布许可。建议使用 LGPL 构建并配合硬件编码器 / 系统编码器，或者软件本身以 GPL 开源，这一点需要在发布前定下来。

### 加密格式插件（qmc / mgg / mflac 等）

- **不随主程序发布**。主程序只提供一个插件接口：输入文件，输出标准音频流。
- 用户自行安装插件并勾选“仅用于本人已购买的内容”后才启用；未启用时这些文件在库里显示为“加密格式”，可以看到但不会处理。
- 这样做是因为绕过平台加密在不少地区存在版权法和服务条款风险，把它与主程序隔离可以让主程序本身保持干净。

## 6. 小说阅读器

- TXT：自动识别编码，按“第 X 章 / 卷”等规则切分章节；大文件按章懒加载。
- EPUB：解包后在隔离的 iframe 里渲染，保留原书排版，可切换为统一排版。
- 功能：字号、行距、字体、纸张 / 护眼 / 夜间主题、书签、阅读进度、全文搜索、朗读（调用 Windows 自带语音）。
- MOBI / AZW3 放在后续版本。

## 7. 界面、桌面常驻与 OLED 防烧屏

**界面**：10 款原型见 `demos/`。正式版把配色、圆角、字体、动效做成主题变量，选定一款作为默认，其余可以作为可切换皮肤保留。

**桌面常驻的三种形态**

| 形态 | 说明 |
| --- | --- |
| 沉浸模式 | 无边框全屏，只留唱片 / 可视化和歌词，控件自动隐藏 |
| 迷你播放器 | 置顶小窗，显示封面、当前歌词和基本控制 |
| 壁纸模式 | 把窗口嵌到桌面图标下方，成为会动的桌面壁纸（Windows 上通过挂载到桌面的 WorkerW 窗口实现，属于非官方做法，放在后期并保留开关） |

**OLED 防烧屏（每项单独开关，demo 中已可体验）**

| 选项 | 作用 |
| --- | --- |
| 纯黑背景 | 背景 `#000`，像素完全熄灭 |
| 像素位移 | 整个画面定时偏移几个像素 |
| 元素漂移 | 唱片、歌词、时钟等沿不规则轨迹缓慢游走 |
| 无操作自动变暗 | 静止一段时间后降低亮度，动一下恢复 |
| 自动隐藏静态控件 | 按钮、进度条、标题栏淡出 |
| 压低静态元素亮度 | 侧边栏、图标等降到一半亮度 |
| 像素刷新 | 全屏轮流显示纯色，让子像素均匀工作 |

另外，全屏播放视频或沉浸模式下阻止系统休眠；暂停超过设定时间后恢复系统屏保。

## 8. 数据存储

- `%APPDATA%\<应用名>\library.db`：媒体库、播放列表、播放历史、阅读进度、设置
- `%LOCALAPPDATA%\<应用名>\cache\`：封面缩略图、联网元数据缓存，可一键清理
- 不修改用户的原始文件；写入标签、重命名整理等操作都需要用户明确确认

主要数据表：`files`（所有文件）、`tracks` / `albums` / `artists`、`videos` / `series` / `episodes`、`books` / `chapters`、`playlists`、`play_state`、`scan_roots`、`jobs`（转换任务）。

## 10. 风险与待定事项

| 风险 | 应对 |
| --- | --- |
| mpv 画面与透明 WebView 叠放在部分显卡驱动上可能闪烁 | M0 先验证；备选方案是 mpv 渲染到纹理再交给前端画布 |
| FFmpeg 许可证 | 发布前确定 LGPL 构建还是整体 GPL |
| 全盘扫描耗时、MFT 需要管理员权限 | 默认普通遍历 + 后台进行；MFT 作为可选加速 |
| 加密格式的法律风险 | 插件化、默认不带、仅限已购内容 |
| 壁纸模式依赖系统未公开行为 | 后期实现，保留开关，Windows 更新后需要回归测试 |
| AI 接口费用不可控 | 开始任务前估算用量并显示；可设每月上限；提供本地模型作为免费替代 |
| 漫画翻译在复杂画面上效果不稳定 | 第一版只处理对话气泡；拟声词和画面内文字默认跳过；所有结果可逐句修改 |
| 自动获取涉及版权和站点规则 | 只使用用户自己添加的来源；不绕过付费、登录、DRM、验证码；详见第 16 节 |

**需要你决定的事**

1. 软件是否开源（影响 FFmpeg 的打包方式）。
2. AI 功能以云端 API 为主还是本地模型为主（影响安装包大小和对显卡的要求，也可以两者都做，默认用云端）。
3. 自动获取的第一版范围：建议先做“订阅链接 + 自动下载 + 自动归类”，AI 解析任意网页放到第二步，理由见第 16 节。

## 11. 番剧与漫画

**番剧（剧集式）**

- 三层结构：番剧 → 季 → 集。列表页是海报墙，点进去是详情页：横幅、简介、季切换、每一集的缩略图、时长、观看进度、字幕状态。
- “继续观看”永远指向下一集未看完的位置；看完一集自动标记，可手动标记整季。
- 每集显示字幕状态：内封字幕、外挂字幕、AI 字幕、无字幕。缺字幕的可以单集或整季交给 AI 字幕（第 14 节）。
- 筛选：在追、已看完、未看、缺字幕。
- 特别篇、OVA、剧场版归到“第 0 季 / 特别篇”，不打乱正片集数。

**漫画**

- 支持 CBZ / ZIP、CBR / RAR、7z、PDF、图片文件夹。PDF 用 PDFium 渲染（`pdfium-render`），压缩包直接流式读取，不解压到磁盘。
- 三种阅读方式：单页、双页（可选右→左，适合日漫）、长条滚动（适合条漫）。
- 按“系列 → 卷 / 话”整理，记住每一本读到第几页；预读前后几页保证翻页不卡。
- 可以对整话或整卷做 AI 翻译嵌字（第 15 节）。

## 12. 音乐库：搜索、分组与快捷播放

- **搜索**：顶部全局搜索框同时搜歌曲、艺人、专辑、番剧、漫画、视频、小说，结果分组显示；支持拼音首字母。底层用 SQLite FTS5。
- **智能列表**（自动维护，不用手动整理）：常听、最近添加、最近播放、我的收藏、无损音质、很久没听、从未播放。每个列表卡片上有播放键，一键播放整组。
- **分组浏览**：按艺人、专辑、格式、文件夹、年份分组，每组可单独播放。
- **排序**：播放次数、添加时间、标题、时长。
- **自定义智能列表**：用规则组合，比如“播放次数大于 20 且格式为无损且最近 30 天听过”。
- 需要的数据：每首歌记录播放次数、最后播放时间、跳过次数、添加时间、收藏标记。只有播放超过一半才计一次播放。

## 13. 格式转换：完成后回写

转换完成后的四种处理方式，可设默认值，也可每个任务单独选：

| 方式 | 行为 |
| --- | --- |
| 加入媒体库，保留原文件 | 新文件进输出目录并入库，原文件不动 |
| 替换原文件 | 新文件接替原文件在库里的位置，播放次数、收藏、歌单、观看进度全部保留；原文件移到回收站，可撤销 |
| 放在原文件旁边 | 两个版本都在库里，归为同一首 / 同一集的不同版本，播放时可选 |
| 只输出到指定目录 | 不改动媒体库 |

- **替换的安全做法**：先完整写出新文件并校验能正常解码，再把原文件移入回收站，最后更新数据库里的路径。任何一步失败都回滚，不会出现原文件没了、新文件又坏了的情况。
- **快捷转换**：播放栏和每一行歌曲 / 每一集上都有转换按钮，选目标格式和完成后的处理方式即可，不用进转换页面。正在播放的文件被替换时，播放不中断，下一次播放自动用新文件。
- 完成后的每个任务都有“播放 / 在库中显示 / 撤销替换”。

## 14. AI 字幕

目标：给没有字幕的视频或番剧自动生成字幕，时间轴与人声对齐，可选翻译成中文或双语。

**流程**

1. **提取音轨**：FFmpeg 导出 16 kHz 单声道音频。
2. **检测人声**：用轻量的语音活动检测模型（如 Silero VAD，本地运行）找出有人说话的片段。只把这些片段送去识别，既省钱又能减少模型在音乐和静音段“幻听”出字幕。
3. **语音识别**：按人声片段切块发送，返回带时间戳的文字。
4. **断句与对齐**：按标点和停顿重新断句，控制每条字幕的长度和持续时间；把起止时间贴齐到人声片段的边界，这一步决定字幕“跟不跟嘴”。
5. **翻译（可选）**：用大语言模型分批翻译，每批带上前后文和术语表，保证人名、称呼、语气前后一致；整季批量时术语表全季共用。
6. **校对与输出**：在时间轴上逐句查看和修改，然后输出为外挂 `.srt` / `.ass`，或不重新编码直接封装进 MKV。

**已有字幕但不同步**时，可以只做第 4 步：用识别出的人声时间重新对齐现有字幕。

**两种引擎**

| | 云端 API | 本地模型 |
| --- | --- | --- |
| 做法 | 用户填接口地址和密钥，兼容 OpenAI 接口格式的语音识别服务 | 内置 whisper.cpp（`whisper-rs`），首次使用时下载模型 |
| 优点 | 快，不占显卡，安装包小 | 免费、离线、不上传任何内容 |
| 缺点 | 按时长收费，需要联网 | 需要较好的显卡，否则很慢；模型文件 1–3 GB |

翻译同样可以选云端大模型或本地模型，本地翻译质量明显差一些，默认推荐云端。

**AI 服务设置**（全局一处，字幕和漫画翻译共用）：接口地址、密钥、三类模型（语音识别、翻译、图像识别）、测试连接、每月费用上限提醒。密钥用 Windows 凭据管理器加密保存在本机。只发送完成任务必需的内容到用户填写的地址，不经过任何第三方服务器。

## 15. 漫画 AI 翻译嵌字

这是所有功能里最难的一项，做法参考了开源社区里成熟的漫画翻译工具的通用流程，分五步：

1. **找出文字区域**：用专门的漫画文字检测模型定位每个对话气泡和文字块，并判断是横排还是竖排、阅读顺序（日漫从右到左、从上到下）。PDF 如果自带文字层就直接读取，跳过这一步和下一步。
2. **识别原文**：对每个文字块做 OCR。日文竖排用针对漫画训练的 OCR 模型效果最好；也可以把气泡截图交给支持图片输入的大模型识别。
3. **结合上下文翻译**：不是一句一句孤立翻译，而是把整页（必要时整话）的对白按阅读顺序连同术语表一起交给大模型，要求它保持人称、语气、称呼一致，并补出日语里省略的主语。这是避免“翻译得很诡异”的关键。每句给出译文，拿不准的地方附上备选。
4. **擦除原文**：白底气泡直接填充底色；压在画面上的文字用图像修复模型（如 LaMa）补全背景。
5. **嵌入译文**：按气泡形状自动选字号、换行、横排或竖排，文字不超出气泡；字体可选。

**校对界面**（原型里已可体验）：左边是页面，右边是逐句的原文和译文，改右边的文字画面立刻更新；可以切换原文 / 译文 / 对照；单句可以带着前后文重新翻译；术语表可随时增改并应用到全书。

**输出**：永远另存为新文件（如 `书名 [中文].cbz`），原文件不动。翻译数据单独保存，以后可以改译文重新导出而不用重新识别。

**模型放在哪里**：检测、OCR、擦除三步建议用本地模型（ONNX Runtime，`ort` crate），它们体积不大、速度快，而且不用把整页图片上传；翻译用云端大模型。这样一页的云端开销只有几百个字的文本。

**第一版的边界**

- 只处理对话气泡和旁白框。拟声词、画面里的招牌等艺术字默认跳过，可手动框选后处理。
- 效果会因画风而异，所以流程设计成“AI 出初稿，人来确认”，而不是完全无人值守。
- 仅用于用户本人拥有的漫画，供个人阅读。

## 16. 自动获取与归类

需求：用户填一个自己常用的来源，在软件里搜番剧或音乐，找到后自动下载整季 / 整张专辑，并自动整理到媒体库。

### 调研：现有工具怎么做

| 工具 | 做法 | 问题 |
| --- | --- | --- |
| Sonarr / Radarr / Lidarr + 索引器 + 下载器 | 追剧、追电影、追音乐的全自动方案，功能最全 | 要装三四个程序分别配置，对普通用户门槛很高 |
| AutoBangumi 一类 | 订阅 RSS，交给 qBittorrent 下载，自动重命名 | 依赖 Docker 和下载器，只管番剧 |
| 下载器自带的 RSS 订阅 | 能自动下，但不整理、不重命名 | 下完还是一堆乱名字的文件 |
| yt-dlp | 支持大量视频和音乐网站的下载 | 命令行工具，没有整理和入库 |

共同的痛点是**配置复杂、各管一段**。我们的机会是把“来源 → 下载 → 整理 → 入库 → 补元数据和字幕”做成一条线，用户只需要做两件事：添加来源、点一下想要的作品。

### 方案

```
来源适配器 ──▶ 搜索 / 订阅 ──▶ 选集规则 ──▶ 下载引擎 ──▶ 自动整理 ──▶ 入库
（用户自己添加）              （字幕组、清晰度、   （内置 aria2，     （识别番剧 / 季 / 集，
                               合集优先、去重）     或对接已装的       重命名并移动到指定目录）
                                                   qBittorrent）
```

**来源适配器**（软件不自带任何来源，全部由用户添加）

| 类型 | 说明 | 稳定性 |
| --- | --- | --- |
| 订阅链接（RSS） | 很多站点和下载器都支持，结构固定 | 高 |
| yt-dlp 支持的网站 | 填作品或播放列表的网址即可 | 高，随 yt-dlp 更新 |
| 自己的网盘或 NAS | WebDAV、SMB、FTP 目录 | 高 |
| 任意网页（AI 解析） | 用户填网站地址，AI 读一次搜索结果页的结构，生成一份“提取规则”保存下来，之后复用 | 中，网站改版后需要重新生成 |
| 自定义脚本 | 给会写代码的用户留的插件接口 | 取决于脚本 |

**AI 在这里的作用**，按价值排序：

1. **理解标题**：从杂乱的发布名里识别作品、季、集、字幕组、清晰度、是否合集，并把同一部作品的不同写法（中文名、日文名、罗马音、缩写）对应起来。
2. **挑选版本**：按用户偏好（比如“简中字幕、1080p、优先合集”）在多个结果里选最合适的，集数有缺口时自动补齐、避免重复下载。
3. **解析陌生网页**：只在用户添加“任意网页”类来源时用一次，生成规则后日常搜索不再消耗 AI 额度。

**自动整理**：下载完成后识别内容，重命名并移动到设定的目录，例如：

```
番剧\作品名\Season 01\作品名 - S01E03.mkv
音乐\艺人\专辑 (年份)\03 - 曲名.flac
```

目录结构和命名模板可改。音乐文件缺标签时用音频指纹（Chromaprint / AcoustID）匹配曲目信息。入库后按设置自动补元数据，缺字幕的番剧可以自动排进 AI 字幕队列。

**追更**：订阅一部连载中的番剧后，新一集发布时自动下载、整理、入库，并在番剧页显示“有更新”。

### 边界与风险（需要先说清楚）

- **软件不提供内容，也不内置任何资源站**。下载什么、从哪里下，由用户添加的来源决定，用户需要确保自己有权获取这些内容（已购买的、官方免费的、公有领域或开放授权的、自己网盘里的）。
- **不做绕过**：不绕过付费墙、会员限制、DRM 加密、验证码和网站的反爬措施。需要登录的来源只使用用户自己的登录状态访问其本来就能访问的内容。
- **尊重站点**：限制请求频率，遵守站点的 robots 规则，避免给对方服务器造成压力，也避免用户的 IP 被封。
- **安全**：只接受媒体类文件，可执行文件一律丢弃；下载目录与媒体库隔离，整理通过后才移入。
- **稳定性**：“任意网页”类来源天然脆弱，网站一改版就会失效，这是所有同类工具的通病。

### 建议的分步做法

1. **第一步**：订阅链接 + yt-dlp + 网盘目录三类来源，内置下载引擎，自动整理入库，追更。这部分技术成熟，做出来就已经比现有方案省事很多。
2. **第二步**：AI 理解标题和挑选版本，把“搜一下、点一下”做到位。
3. **第三步**：AI 解析任意网页生成规则。放在最后是因为它最不稳定、维护成本最高，而且前两步已经能覆盖大多数常见来源。
