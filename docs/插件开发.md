# 插件开发说明

插件是一个带 `plugin.json` 的文件夹，或者把这个文件夹打成的 `.mpx` 包（就是 zip）。插件给“自动获取”接入新的**下载源**：音乐、视频、番剧、漫画、小说都行。装好后：

- 下载源出现在“自动获取 → 我的来源”的“插件”分组里，每个下载源可以单独开关，旁边显示最近一次调用的状态；
- 搜索页的“搜索范围”里可以只选某几个来源，结果上方列出每个来源搜到几条、哪个来源出错及原因；
- 下载走同一个队列（暂停 / 继续 / 取消 / 重试），下完补标签、存歌词，按原来的规则整理入库。

插件在“设置 → 插件”里管理：“已安装”“仓库”“开发者”三页。点开一个插件是详情窗口，有“概况与设置”“测试”“日志”三页。

> 软件不内置任何第三方网站的插件，也不内置任何插件仓库地址。只给你有权获取内容的服务写插件：官方开放接口、自己的 NAS / 网盘 / 媒体服务器、已购买且允许下载的内容、公有领域或 CC 授权的资源。插件不能替用户登录、不能过验证码、不能绕过 DRM、付费或会员限制，见第 13 节。

实现：`src-tauri/src/plugin/`（`manifest.rs` 清单、`package.rs` 插件包、`process.rs` 协议 2、`source.rs` 插件下载源、`js.rs` 沙箱、`repo.rs` 仓库、`mod.rs` 安装和设置），数据格式在 `src-tauri/src/fetch/provider.rs`。

模板和示例：

| 路径 | 内容 |
| --- | --- |
| `tools/plugin-templates/python/` | process 入口，Python，只用标准库 |
| `tools/plugin-templates/node/` | process 入口，Node.js，演示交给 yt-dlp 下载 |
| `tools/plugin-templates/js-sandbox/` | js 入口（沙箱），用 `mp.http` + `mp.html` 抓网页，漫画按话给图片地址 |
| `tools/plugin-templates/em/` | rule 入口，把一个 .em 下载源规则包装成插件 |
| `tools/plugin-examples/local-library/` | 完整示例：在自己的曲库文件夹里搜索，插件自己“下载”（复制）文件 |
| `tools/mpplugin_check.py` | 命令行检查工具：检查 plugin.json，按协议 2 实际调用 process 插件 |
| `tools/plugin.schema.json` | plugin.json 的 JSON Schema，编辑器里可以用来补全和检查 |

## 1. 概览

### 三种入口

| | rule（规则） | js（脚本，沙箱） | process（程序） |
| --- | --- | --- | --- |
| 写什么 | 一个 `kind: source` 的 .em 文件（YAML，不写代码） | 一个 JavaScript 文件（ES 模块） | 任意程序：Python、Node、exe…… |
| 在哪运行 | 软件的规则引擎 | 软件内置的 QuickJS 沙箱 | 用户电脑上的普通进程 |
| 联网 | 软件代为请求，只能访问声明的网站 | 同左（`mp.http`） | 程序自己联网，软件管不了 |
| 读写文件 | 不能 | 不能 | 能 |
| 能力 | search / episodes / resolve | search / episodes / resolve | search / episodes / resolve / download |
| 信任级别 | 受限（limited） | 受限（limited） | 完全信任（full） |
| 用户要装什么 | 不用 | 不用 | 解释器（python、node）或你打包好的 exe |

怎么选：

- 网站是普通网页或 JSON 接口，几个请求就能拿到下载地址 → **rule**。最省事，见 [rules/source.md](rules/source.md)。
- 需要写逻辑（拼参数、多步跳转、解析复杂页面），但不需要碰文件 → **js**。用户安装时不用信任你的程序，最容易被接受。
- 需要读本地文件、调用自己的命令行工具、自己下载和合并文件、用第三方库 → **process**。安装时用户会看到“这是一个程序插件”的醒目提示，要勾选“我信任这个插件的来源”。

### 插件包

```
my-plugin/
├─ plugin.json      必须在根目录
├─ main.py          入口（process 的命令里写的文件、js / rule 的 runtime.file）
├─ icon.png         可选，plugin.json 的 icon
├─ README.md        可选，安装确认页和插件详情里显示（前 8000 字）
└─ …                其他文件随意
```

- 可以直接安装文件夹，也可以打成 `.mpx`：把文件夹里的文件压成 zip、扩展名改成 `.mpx`。`plugin.json` 在 zip 根目录，或者在 zip 里唯一的一层文件夹里（直接压缩整个文件夹时常见）都行。
- 限制：解压后不超过 200 MB、不超过 5000 个文件；不能有绝对路径、`..`、符号链接；`plugin.json` 不超过 256 KB，UTF-8 编码。
- 从仓库下载的 `.mpx` 不超过 50 MB。
- 打包和算摘要时跳过 `__pycache__`、`node_modules`、`.git` 文件夹。要用 Node 的第三方库，请先打包成单个文件，或者把依赖放到别的文件夹名下。

### 下载源 id

插件的每个下载源注册成一个下载源 id，下载任务和追更都记这个 id：

| 入口 | 下载源 id |
| --- | --- |
| process / js，源 id 是 `main` | `plg-<插件 id>`，如 `plg-local-library` |
| process / js，其他源 id | `plg-<插件 id>.<源 id>`，如 `plg-my-site.video` |
| rule | `em-<.em 里的规则 id>`，如 `em-my-em-source` |

插件 id 和源 id 发布以后就不要再改：改了等于换了一个下载源，之前的追更和没下完的任务会找不到它。插件停用或卸载时，相关任务会提示“插件已停用，启用后可以继续”或“插件已卸载”。

### 能力（capabilities）

| 能力 | 方法 | 说明 |
| --- | --- | --- |
| `search` | `search` | 必须有。按关键字搜索 |
| `episodes` | `episodes` | 一部作品 → 各集 / 话 / 章。有这个能力时，搜索结果里**没有 `episode` 的前 3 条**会被展开成各集（展开失败就保留原条目并记一条警告日志） |
| `resolve` | `resolve` | 一条结果 → 下载方式（直链、yt-dlp、磁力、图片列表、章节正文），由软件下载 |
| `download` | `download` | 插件自己把文件下到软件给的文件夹里（只有 process 能用） |

`resolve` 和 `download` 至少要有一个。两个都写时软件只用 `resolve`，`download` 不会被调用。

process 入口另外还有一个 `info` 方法（不用声明）：安装后和测试时调用一次做自检，见第 3 节。

## 2. plugin.json

### 完整例子

```jsonc
{
  "manifest": 1,                       // 清单格式版本，写 1
  "id": "my-site",                     // 插件 id
  "name": "我的网站",                   // 显示名
  "version": "1.2.0",                  // 主.次.修
  "author": "你的名字",
  "description": "一句话说明，显示在安装确认页和插件列表里",
  "homepage": "https://example.org/my-site-plugin",
  "license": "MIT",
  "icon": "icon.png",
  "engines": { "app": ">=0.5.0", "protocol": 2 },
  "runtime": {
    "type": "process",
    "command": {
      "default": ["python", "main.py"],
      "macos": ["python3", "main.py"],
      "linux": ["python3", "main.py"],
      "windows": ["bin/my-site.exe"]
    }
  },
  "contributes": {
    "sources": [
      { "id": "main", "name": "我的网站 · 音乐", "media_kinds": ["music"],
        "capabilities": ["search", "resolve"], "note": "需要你自己的账号" },
      { "id": "video", "name": "我的网站 · 视频", "media_kinds": ["video", "anime"],
        "capabilities": ["search", "episodes", "resolve"] }
    ],
    "rules": []
  },
  "permissions": {
    "hosts": ["example.org", "*.cdn.example.org"],
    "login": "optional",
    "tools": ["ytdlp"],
    "paths": []
  },
  "settings": [
    { "key": "token", "type": "secret", "label": "访问令牌", "help": "在网站的“开发者设置”里生成" },
    { "key": "quality", "type": "select", "label": "默认音质", "default": "flac",
      "options": [{ "value": "flac", "label": "无损" }, { "value": "mp3", "label": "MP3 320K" }] },
    { "key": "max_results", "type": "int", "label": "最多显示几条", "default": 30 }
  ],
  "legacy_ids": ["ext-my-site"]
}
```

（`jsonc` 只是为了写注释，真正的 plugin.json 是标准 JSON，不能有注释。）

### 字段

不认识的字段会被忽略；类型写错（比如 `id` 写成数字）整个文件读不了。

| 字段 | 类型 | 默认 | 说明和检查规则 |
| --- | --- | --- | --- |
| `manifest` | 整数 | — | 必填，写 `1`。比软件认识的大时提示“需要更新版本的软件” |
| `id` | 字符串 | — | 必填。小写字母、数字、`-`，3–64 位，不能以 `-` 开头或结尾 |
| `name` | 字符串 | — | 必填，不能是空白 |
| `version` | 字符串 | — | 必填。`主.次.修`，后面可以带 `-beta.1`、`+build` 之类（比较大小时只看前三段） |
| `author` / `description` / `homepage` / `license` | 字符串 | 空 | 显示用 |
| `icon` | 字符串 | 空 | 图标文件，相对插件文件夹，不能含 `..`；写了文件就必须存在 |
| `engines.app` | 字符串 | 空（不限） | 最低软件版本，写成 `>=0.5.0`（`^0.5.0`、`0.5.0` 也按“不低于”处理；`*` 表示不限）。软件版本不够时不能安装 |
| `engines.protocol` | 整数 | 0 | process 写 `2`（`1` 是旧协议，只支持 search / resolve）；js 只能写 `2`；rule 不用写 |
| `runtime.type` | 字符串 | — | 必填：`rule` / `process` / `js` |
| `runtime.command` | 对象 | — | process 必填。键是 `windows` / `macos` / `linux` / `default`，值是命令数组。先找当前系统的键，没有再用 `default` |
| `runtime.file` | 字符串 | — | rule / js 必填。入口文件，相对插件文件夹，不能含 `..`，必须存在 |
| `contributes.sources` | 数组 | `[]` | 提供的下载源，见下表。rule 入口最多一个 |
| `contributes.rules` | 字符串数组 | `[]` | 随插件一起安装的其他 .em 规则（比如配套的漫画排版规则），相对路径，必须存在且能读 |
| `permissions.hosts` | 字符串数组 | `[]` | 要访问的网站，见第 10 节 |
| `permissions.login` | 字符串 | `none` | `none` / `optional` / `required`。不是 `none` 时必须写 `hosts` |
| `permissions.tools` | 字符串数组 | `[]` | 要用软件自带的哪些程序：`ytdlp` / `ffmpeg` / `ffprobe`（只对 process 有用） |
| `permissions.paths` | 字符串数组 | `[]` | 要读写的文件夹，只能写 `setting:<设置项 key>`，引用的设置项必须存在 |
| `settings` | 数组 | `[]` | 设置项，见第 9 节 |
| `update.index` | 字符串 | 空 | 预留：插件自己的仓库索引地址。目前软件不读它，更新只看用户添加的仓库 |
| `legacy_ids` | 字符串数组 | `[]` | 这个插件替代的旧下载源 id（`ext-` 开头的外部程序或 `em-` 开头的规则）。安装时把“我的来源”里的旧来源、追更和没下完的任务转到插件的第一个下载源上 |

`contributes.sources` 的每一项：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | 字符串 | 必填。小写字母、数字、`-`，1–64 位，不能以 `-` 开头或结尾，插件内不重复。只有一个下载源时写 `main` |
| `name` | 字符串 | 显示名，不写用插件的 `name` |
| `media_kinds` | 字符串数组 | `music` / `video` / `anime` / `manga` / `novel`。搜索页当前类型不在里面时不会调用这个下载源；不写表示全部 |
| `capabilities` | 字符串数组 | 见第 1 节。必须有 `search`；`resolve`、`download` 至少一个；rule / js 不能有 `download`；协议 1 只能有 `search`、`resolve` |
| `note` | 字符串 | 一句话说明，显示在来源列表里 |

### 命令怎么写（process）

- 第一项是要运行的程序：相对路径（含 `/` 或 `\`，或者带扩展名，如 `main.exe`、`bin/tool`）按插件文件夹找，必须存在；其他（`python`、`node`）按系统 PATH 找。不能写绝对路径。
- 软件在命令后面追加方法名：`python main.py search`。工作目录是插件文件夹。
- Windows 上通常是 `python`，macOS / Linux 上通常只有 `python3`，所以像上面的例子那样按系统分开写。不想让用户装 Python，就用 PyInstaller 之类打成 exe，写在 `windows` 里。

插件包安装前、开发者模式加载时、每次启动时都会按这些规则检查一遍；有问题时列出所有问题，不能安装，已装的会停用并在插件列表里显示原因。`tools/mpplugin_check.py` 和 `tools/plugin.schema.json` 用的是同一套规则。

## 3. process 入口（协议 2）

### 调用方式

每次调用启动一次进程：

```
<runtime.command…> <方法>
```

1. 软件把一个请求 JSON 写进**标准输入**，然后关闭标准输入；
2. 插件往**标准输出**一行写一个事件（JSON Lines，UTF-8，每行一个完整的 JSON 对象，以换行结尾）；
3. 最后一个事件是 `result` 或 `error`，然后退出。

请求：

```json
{
  "protocol": 2,
  "method": "search",
  "params": { "source": "main", "query": "晴天", "media_kind": "music", "page": 1 },
  "settings": { "library_dir": "D:\\Music", "max_results": 50, "token": null },
  "context": { "app_version": "0.5.0", "lang": "zh-CN", "cookies": {} }
}
```

- `params.source`：调用的是哪个下载源（`contributes.sources[].id`），一个插件有多个下载源时用它区分。
- `settings`：所有设置项的当前值（没保存过的用 `default`，secret 从系统凭据管理器取出来，没填是 `null`）。必填设置没填时软件直接报 `bad_config`，不会启动插件。
- `context.cookies`：`{ "域名": "Cookie 请求头的值" }`。只有插件声明了 `login`、用户同意交出登录、并且用户在“网站登录”里登录过这个网站时才有；只给 `hosts` 里没有 `*.` 的域名。

### 方法

| 方法 | params | result 的 data | 时限 |
| --- | --- | --- | --- |
| `info` | `{source}` | 任意对象，建议 `{"ok": true, "message": "一句话状态"}`；`message` 显示在测试面板 | 15 秒 |
| `search` | `{source, query, media_kind, page}` | `Item` 数组，或 `{"items": [...], "has_more": false}` | 60 秒 |
| `episodes` | `{source, item}` | `Item` 数组（各集） | 60 秒 |
| `resolve` | `{source, item, quality}` | `Resolved`：`{"target": {...}, "lyric": null}` | 120 秒 |
| `download` | `{source, item, quality, dest_dir, resume}` | `{"files": [{"path": "...", "role": "main"}]}` | 24 小时；300 秒没有任何输出就停 |

- `page` 从 1 开始。目前搜索页只要第 1 页；`has_more` 先照写，软件暂时不用。一次就给出全部结果的插件，`page > 1` 时返回空数组。
- `item` 是你在 `search` / `episodes` 里返回的那一条（经过软件补齐默认值），`extra` 原样带回。
- `quality` 是用户选的 `Quality.key`；空串表示默认档位（你给的第一个）。
- 不认识的方法返回 `unsupported` 错误。以后软件可能加新方法。

### 事件

```json
{"event": "log", "level": "info", "msg": "请求第 1 页"}
{"event": "progress", "done": 1048576, "total": 5242880, "unit": "bytes", "speed": 262144, "text": "正在下载"}
{"event": "result", "data": [ ... ]}
{"event": "error", "code": "login_required", "message": "请先在“网站登录”里登录 example.org"}
```

| 事件 | 字段 | 说明 |
| --- | --- | --- |
| `log` | `level`（`info` / `warn` / `error` / `debug`，默认 `info`）、`msg` | 记进插件日志 |
| `progress` | `done`（数字）、`total`（数字，可选）、`unit`（`bytes` / `pages` / `items`）、`speed`（字节 / 秒，可选）、`text`（可选） | 只在 `download` 里有用，见第 8 节 |
| `result` | `data` | 结果。有多个时以最后一个为准 |
| `error` | `code`、`message` | 错误码见第 8 节；不认识的错误码按 `internal` 处理 |

其他规则：

- 不以 `{` 开头的行、解析不了的行都当作 `info` 日志；`event` 不认识的行当作警告日志。所以 `print("调试信息")` 不会搞坏协议，但结果一定要用 `result` 事件输出。
- 标准错误的最后 20 行在调用结束后记进日志（级别 `stderr`）。没有输出 `result` / `error` 且退出码不是 0 时，标准错误的最后一行就是错误提示。
- 退出码是 0 但没有 `result` / `error`：报“插件没有输出 result 或 error 事件”。
- 一行最长 32 MB，整个标准输出最多 64 MB，超过就停掉插件。
- 超过时限、用户暂停或取消下载时，软件结束**整个进程树**（插件启动的 yt-dlp、ffmpeg 等子进程一起结束）。Windows 上不弹黑框。
- 输出要用 UTF-8。软件已经设了 `PYTHONIOENCODING=utf-8`、`PYTHONUTF8=1`；Python 里最稳的写法是 `sys.stdout.buffer.write((json.dumps(x, ensure_ascii=False) + "\n").encode("utf-8"))` 再 `flush()`。
- 每次调用都是新进程，不要指望内存里的状态能留到下一次；要缓存就写进 `MP_PLUGIN_DATA`。

### 环境变量

| 变量 | 内容 |
| --- | --- |
| `MP_PROVIDER_PROTOCOL` | `2` |
| `MP_PLUGIN_ID` | 插件 id |
| `MP_PLUGIN_DIR` | 插件文件夹（只读对待：安装后改了里面的文件，插件会被停用，见第 10 节） |
| `MP_PLUGIN_DATA` | 插件自己的可写文件夹（缓存、令牌刷新结果等），卸载时选“连设置一起删”才会删除 |
| `MP_TEMP` | 系统临时文件夹 |
| `MP_LANG` | `zh-CN` |
| `MP_APP_VERSION` | 软件版本 |
| `MP_YTDLP` / `MP_FFMPEG` / `MP_FFPROBE` | 软件自带程序的完整路径，只有在 `permissions.tools` 里声明了的才有 |

### 一次完整的对话

`python main.py search`，标准输入：

```json
{"protocol":2,"method":"search","params":{"source":"main","query":"晴天","media_kind":"music","page":1},"settings":{"library_dir":"D:\\Music","max_results":50},"context":{"app_version":"0.5.0","lang":"zh-CN","cookies":{}}}
```

标准输出：

```
{"event": "log", "level": "info", "msg": "扫描 D:\\Music"}
{"event": "result", "data": [{"id": "周杰伦/叶惠美/03 - 晴天.flac", "title": "晴天", "artist": "周杰伦", "album": "叶惠美", "track": 3, "media_kind": "music", "qualities": [{"key": "orig", "label": "FLAC", "format": "flac", "size": 31457280}]}]}
```

用户点下载后，`python main.py download`，标准输入：

```json
{"protocol":2,"method":"download","params":{"source":"main","item":{"id":"周杰伦/叶惠美/03 - 晴天.flac","title":"晴天","artist":"周杰伦","album":"叶惠美","year":null,"track":3,"duration":null,"cover":"","media_kind":"music","series":"","season":null,"episode":null,"qualities":[{"key":"orig","label":"FLAC","format":"flac","bitrate":null,"size":31457280}],"extra":null},"quality":"orig","dest_dir":"D:\\下载\\plg-42","resume":false},"settings":{"library_dir":"D:\\Music","max_results":50},"context":{"app_version":"0.5.0","lang":"zh-CN","cookies":{}}}
```

标准输出：

```
{"event": "progress", "done": 1048576, "total": 31457280, "unit": "bytes"}
{"event": "progress", "done": 2097152, "total": 31457280, "unit": "bytes"}
…
{"event": "result", "data": {"files": [{"path": "D:\\下载\\plg-42\\03 - 晴天.flac", "role": "main"}, {"path": "D:\\下载\\plg-42\\03 - 晴天.lrc", "role": "lyric"}]}}
```

出错时：

```
{"event": "error", "code": "bad_config", "message": "找不到曲库文件夹：D:\\Music"}
```

### download 的约定

- 文件必须下到 `dest_dir` 里（软件为每个任务建的空文件夹）。返回的路径不在 `dest_dir` 里、或者文件不存在，任务失败。
- `files` 至少有一个 `role: "main"`。字幕、歌词、封面会被改名成和第一个主文件同名（扩展名不变）。
- `resume: true` 表示上次没下完，`dest_dir` 里留着上次的文件。建议先写到 `.part` 文件，下完再改名，续传时接着写。
- 用户暂停 / 取消时进程直接被结束，没有清理的机会；下次继续时会重新调用 `download`，`resume` 为 `true`。
- 音乐的主文件下完后软件会用 `item` 补缺失的标签。

### 协议 1（旧）

协议 1 是“外部程序下载源”的老协议（[下载源接口.md](下载源接口.md) 第 9 节）：标准输出直接是结果 JSON，没有事件。插件里请一律用协议 2。

## 4. js 入口（沙箱）

`runtime.file` 指向一个 ES 模块。每个方法是一个**导出函数**，参数是 `(params, mp)`，返回值就是结果；可以是普通函数，也可以是 `async` 函数。`params` 和 process 的一样（含 `source`），但没有 `download`，也没有 `info`。

```js
export function search({ query, page }, mp) {
  const r = mp.http.get("https://example.org/s?" + mp.url.query({ q: query, p: page }));
  return mp.html.select(r.text, "li.item a").map((a, i) => ({
    id: mp.url.resolve(r.url, a.attrs.href),
    title: a.text,
    extra: { href: mp.url.resolve(r.url, a.attrs.href) },
  }));
}

export function resolve({ item }) {
  return { target: { type: "http", url: item.extra.href, ext: "mp3" } };
}
```

没导出的方法被调用时报 `unsupported`。

### mp.http

| 函数 | 说明 |
| --- | --- |
| `mp.http.get(url, opts?)` | GET |
| `mp.http.post(url, opts?)` | POST |
| `mp.http.json(url, opts?)` | 请求并按 JSON 解析返回的 `text`；有 `form` 或 `json` 时默认 POST，否则 GET；解析不了抛 `internal` |
| `mp.http.request(opts)` | 完整写法，`opts.url`、`opts.method` 必填 |

`opts`：

| 字段 | 说明 |
| --- | --- |
| `method` | `GET` / `POST`，其他报 `unsupported` |
| `headers` | 只能有 `Referer`、`Accept`、`Accept-Language`（不分大小写）；写了别的（包括 `Cookie`、`User-Agent`、`Authorization`）直接报 `forbidden` |
| `form` | 对象，按表单提交 |
| `json` | 任意值，按 JSON 提交（和 `form` 二选一，`form` 优先） |
| `encoding` | 返回内容的编码：`utf-8` / `gbk` / `big5` …；不写自动识别 |

返回 `{ url, status, text }`：`url` 是跳转后的最终地址，`status` 是 HTTP 状态码，`text` 是解码后的正文。

**函数是同步的**（直接返回结果，不是 Promise），所以不用 `await`。

联网规则和 .em 规则相同（`src-tauri/src/em/net.rs`）：

- 只能访问 `permissions.hosts` 里的网站，每一次跳转都检查；跳到别的网站报 `forbidden`。
- 本机、局域网地址只有在 `hosts` 里原样写出时才能访问（`*.` 通配不算）。
- 只能 http / https，网址里不能带用户名密码。
- 单个响应最大 8 MB，单个请求 30 秒超时，同一个网站请求之间至少间隔 1 秒，一次调用最多 2000 个请求。
- User-Agent 由软件固定。
- 用户同意交出登录时，软件自动给请求带上他在“网站登录”里保存的 Cookie；插件看不到 Cookie 的值。
- 401、登录页 → `login_required`；403、访问了没声明的网站 → `forbidden`；404 → `not_found`；429 → `rate_limited`；其他连接失败、超时 → `network`。这些都是抛出的 `PluginError`，不 catch 就直接成为这次调用的错误。

### mp.html

| 函数 | 返回 |
| --- | --- |
| `mp.html.select(html, css)` | 数组，每项 `{ text, html, attrs }`，最多 5000 项 |
| `mp.html.selectOne(html, css)` | 第一项，没有时 `null` |

- `text`：元素里的全部文字，连续空白合并成一个空格，去掉首尾空白。
- `html`：元素的内部 HTML，可以再传给 `select` 继续找。
- `attrs`：属性对象，如 `a.attrs.href`、`img.attrs["data-src"]`。
- CSS 选择器写错报 `internal`。

### mp.url

| 函数 | 说明 |
| --- | --- |
| `mp.url.resolve(base, rel)` | 相对地址补全成绝对地址 |
| `mp.url.encode(s)` | 同 `encodeURIComponent` |
| `mp.url.query(obj)` | `{q: "a b", p: 1}` → `q=a%20b&p=1`，跳过 `undefined` / `null` |

### 其他

| 名字 | 说明 |
| --- | --- |
| `mp.log(...args)` / `mp.log.info` / `.warn` / `.error` / `.debug` | 写插件日志；非字符串参数按 JSON 显示，单条最多 4000 字 |
| `console.log` / `info` / `warn` / `error` / `debug` | 同上 |
| `mp.settings` | 设置值（只读），和 process 的 `settings` 一样，含 secret |
| `mp.context` | `{ app_version, lang }`（没有 `cookies`） |
| `PluginError` | `throw new PluginError("login_required", "请先登录")`；只给一个参数时错误码是 `internal` |

抛出别的错误（比如 `TypeError`）时报 `internal`，提示里带错误信息和第一行调用栈。

### 沙箱里没有的东西

- 没有 `import` / `require`，不能加载其他文件：要用第三方库，先用 esbuild、rollup 之类**打成一个文件**（格式选 ESM）；
- 没有 `fetch`、`XMLHttpRequest`，联网只能用 `mp.http`；
- 没有文件、进程、`process`、`setTimeout` / `setInterval`。等不到完成的 Promise 会报“插件的 Promise 一直没有完成”；
- 每次调用都是全新的运行环境，全局变量留不到下一次。

限制：入口文件最大 4 MB，UTF-8；内存 64 MB；栈 1 MB；返回值（JSON）最大 16 MB；时限和 process 一样（search / episodes 60 秒，resolve 120 秒），超时报 `network`（“插件运行超时”）。

## 5. rule 入口（.em 规则）

- `runtime.file` 指向一个 `kind: source` 的 .em 文件，写法见 [rules/source.md](rules/source.md)。
- 安装时规则被导入，注册成下载源 `em-<规则 id>`；随插件启停、卸载、更新。规则 id 已经被单独导入过、或属于别的插件时不能安装（先在“设置 → 规则文件”里删掉）。
- `plugin.json` 的 `permissions.hosts` 必须和 .em 里的 `hosts` **完全一样**（顺序无所谓）。
- `contributes.sources` 最多一个，能力写 `search` + `resolve`（.em 有 `episodes` 阶段时加上 `episodes`）。这里的能力只用于检查和显示，实际做什么由 .em 决定。
- 开发者模式不支持 rule 入口：开发时直接在“设置 → 规则文件 → 导入…”里导入 .em，改完保存就生效，用规则自己的测试面板调试。

`contributes.rules` 可以带别的 .em（漫画排版、小说排版、整理规则……），任何入口类型都能带。

## 6. 仓库和更新

仓库就是放在网上的一个 `index.json` 加若干 `.mpx` 文件，任何能放静态文件的地方都行。用户在“设置 → 插件 → 仓库”里粘贴 `index.json` 的地址添加。软件不内置、不推荐任何仓库。

### index.json

```json
{
  "index": 1,
  "name": "我的插件仓库",
  "plugins": [
    {
      "id": "my-site",
      "name": "我的网站",
      "version": "1.2.0",
      "description": "一句话说明",
      "author": "你的名字",
      "url": "my-site-1.2.0.mpx",
      "sha256": "9f2c…（64 位十六进制）",
      "app": ">=0.5.0",
      "runtime": "process",
      "media_kinds": ["music"],
      "hosts": ["example.org", "*.cdn.example.org"],
      "login": "optional",
      "tools": ["ytdlp"]
    }
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `index` | 必填，写 `1` |
| `name` | 仓库显示名 |
| `plugins[].id` / `version` / `url` | 必填。`url` 可以是相对 `index.json` 的地址，只能 http / https |
| `plugins[].sha256` | 必填。`.mpx` 文件本身的 SHA-256（64 位十六进制，不分大小写）。下载后对不上就拒绝安装 |
| `plugins[].app` | 最低软件版本，同 `engines.app`。不满足时显示“需要升级软件”，也不会作为更新 |
| `plugins[].name` / `description` / `author` / `media_kinds` | 仓库列表里显示 |
| `plugins[].runtime` / `hosts` / `login` / `tools` | **和包里的 plugin.json 保持一致**。软件用它们判断新版本是否需要更多权限（决定能不能自动更新） |

同一个 `id` 可以列多个版本，取满足软件版本要求的最高版本。`index.json` 最大 2 MB，`.mpx` 最大 50 MB。

算 sha256：

```
# Windows PowerShell
Get-FileHash my-site-1.2.0.mpx -Algorithm SHA256
# macOS / Linux
shasum -a 256 my-site-1.2.0.mpx
```

### 从仓库安装

点“安装”时软件先下载 `.mpx`、核对 sha256、核对包里的 `id` 和索引一致，然后显示和本地安装一样的确认页（第 10 节）。

### 检查更新和自动更新

- 启动 20 秒后，以及之后每小时看一次：有超过 24 小时没刷新的仓库就全部刷新一遍。也可以在“仓库”页手动刷新。
- 某个已装插件在任一仓库里有更高版本（且满足软件版本要求），插件列表和详情里显示“更新”。
- “自动更新插件”开着时（默认开）：新版本**不需要新权限**的直接安装，记一条日志；需要新权限的（新网站、新工具、开始要用登录、从 rule / js 变成 process）只提示，用户点更新时重新确认。
- 开发者模式加载的插件不参与更新。
- 每次更新（不论自动还是手动）都把旧版本留一份，插件详情里可以“回到上一版本”。只保留一个旧版本，回退后就没有可回退的了。

发新版本的步骤：改 `plugin.json` 的 `version` → 打 `.mpx` → 算 sha256 → 在 `index.json` 里加一项（或改掉旧的）→ 上传。

## 7. 数据格式

和 Rust 里的结构一一对应（`src-tauri/src/fetch/provider.rs`）。**字符串字段不要写 `null`**（没有就不写，或写空串），否则整条读不了；标成“可空”的可以写 `null`。

### Item（搜索结果 / 一集）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | 字符串 | 你自己的编号，**要稳定**（同一条每次搜都一样），追更靠它判断是不是新的 |
| `title` | 字符串 | 必填，空的条目会被跳过 |
| `artist` | 字符串 | 艺人 / 作者。音乐整理入库按艺人归档，建议给 |
| `album` | 字符串 | 专辑 |
| `year` / `track` / `season` | 整数，可空 | 年份、音轨号、第几季 |
| `duration` | 数字，可空 | 时长（秒） |
| `episode` | 数字，可空 | 第几集 / 话 / 章，可以是小数。填了才能追更 |
| `cover` | 字符串 | 封面网址 |
| `media_kind` | 字符串 | 不写时用搜索页当前的类型 |
| `series` | 字符串 | 作品名（番剧 / 漫画 / 小说）：搜索页按它分组，入库按它建文件夹。`episodes` 返回的集没写时用作品的 `series` 或 `title` |
| `qualities` | `Quality` 数组 | 从好到差排，第一项是默认档位 |
| `extra` | 任意 | 你自己用的数据，原样带回 `episodes` / `resolve` / `download` |

`episodes` 返回的集没写 `cover`、`artist` 时用作品的。

### Quality

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `key` | 字符串 | 你自己认得的档位标识，原样传回 `quality` |
| `label` | 字符串 | 显示文字，如“无损”“1080P” |
| `format` | 字符串 | flac / mp3 / mp4 … |
| `bitrate` | 整数，可空 | kbps |
| `size` | 整数，可空 | 字节 |

### Resolved（resolve 的返回）

```json
{ "target": { "type": "http", "url": "https://example.org/a.flac", "ext": "flac" }, "lyric": "[00:01.00]……" }
```

`lyric` 可空，是 LRC 全文，下完存成同名 `.lrc`。

### Target（下载方式）

| `type` | 字段 | 软件怎么下 |
| --- | --- | --- |
| `http` | `url`、`ext`（必填，不带点）、`headers`（可选） | HTTP 直链，断点续传。整本 CBZ / EPUB / PDF 也用这个 |
| `ytdlp` | `url`、`format`（可选） | 交给软件自带的 yt-dlp，见第 12 节 |
| `magnet` | `uri` | 磁力链接或 .torrent 网址，走 BT 下载 |
| `pages` | `urls`（数组）、`headers`（可选） | 漫画一话的全部图片，按顺序下载后打包成 CBZ |
| `chapters` | `chapters`：`[{"title", "text"}]` | 小说若干章的正文（纯文本，一行一段），生成 EPUB |
| `file` | `path` | 已经在本机的文件。协议 1 的旧写法；插件请用 `download` 能力 |

检查（不通过时报 `forbidden`）：

- `http`、`ytdlp`、`pages` 的每个地址都必须在 `permissions.hosts` 里（所有入口都查，process 也一样）。
- `headers` 只能有 `Referer`、`Accept`、`Accept-Language`、`Authorization`，**不能有 `Cookie`**。
- `ytdlp` 的 `format` 见第 12 节。

直链会过期也没关系：每次开始 / 继续下载都会重新调用 `resolve`。

### download 返回的 files

`{"files": [{"path": "…", "role": "main"}]}`，`role` 是 `main`（默认）/ `subtitle` / `lyric` / `cover`，其他值报错。

### 下载后的文件名

软件按 `Item` 起文件名，整理入库时再从文件名认出作品和集数：音乐 / 视频 `歌名 - 艺人.ext`；番剧 `作品名 - 03.ext`（有季时 `作品名 S02E03.ext`）；漫画 `作品名 第03话.cbz`；小说 `书名 - 作者.epub`。所以 `series`、`episode`、`season` 填准很重要。

## 8. 错误码和进度

### 错误码

process 用 `error` 事件，js 用 `throw new PluginError(code, message)`。`message` 是直接给用户看的话，写清楚原因和该怎么办。

| 错误码 | 什么时候用 | 界面上 |
| --- | --- | --- |
| `login_required` | 需要登录、登录过期（401、跳到登录页） | “需要登录”，按钮带用户去“网站登录”自己登录 |
| `captcha` | 网站要求人机验证 | “需要验证”，提示用户在浏览器或“网站登录”里自己完成 |
| `forbidden` | 网站拒绝访问（403）；软件拦下了没声明的网站、不允许的请求头 | “被拒绝”，按钮打开日志 |
| `not_found` | 没有这个内容、地址变了 | “没找到” |
| `rate_limited` | 请求太频繁（429） | “太频繁，过一会儿再试” |
| `network` | 连接失败、超时 | “网络”，按钮打开日志 |
| `bad_config` | 设置没填或不对 | “设置不对”，按钮打开插件设置 |
| `unsupported` | 不支持这个方法 / 这种内容 | “不支持” |
| `internal` | 插件自己的 bug、返回格式不对、没写错误码 | “插件出错”，按钮打开日志 |
| `plugin_disabled` | 软件自己用：插件已停用 | “已停用”，按钮启用插件 |

错误显示在：搜索页每个来源的出错提示、“我的来源”里下载源的状态标记、下载任务的失败原因、测试面板。每个下载源最近一次调用的结果（方法、错误码、说明、时间）都会记下来。

### 进度（只有 download）

```json
{"event": "progress", "done": 3, "total": 12, "unit": "pages", "text": "第 3 / 12 页"}
```

- 有 `total` 时下载列表显示百分比（`done / total`）；没有时只显示“正在下载”。
- `unit` 是 `bytes` 时 `total` 当作文件大小显示；`speed`（字节 / 秒）显示为速度。
- 软件每 0.5 秒最多刷新一次界面，多发没关系；但 **300 秒没有任何输出**（事件、日志都算）会被当作卡死结束掉，长时间的步骤请定时发一条进度或日志。

## 9. 设置

`settings` 里的每一项在插件详情的“概况与设置”页显示成一个输入框。

| 字段 | 说明 |
| --- | --- |
| `key` | 必填，插件内不重复 |
| `type` | `string` / `secret` / `bool` / `int` / `select` / `folder` |
| `label` | 必填，显示名 |
| `help` | 说明文字 |
| `default` | 默认值（`secret` 不支持默认值） |
| `required` | 必填。没填时插件列表提示“要先填设置”，调用直接报 `bad_config`（“先在插件设置里填写‘…’”），不会运行插件 |
| `options` | `select` 必填：`["a", "b"]` 或 `[{"value": "a", "label": "A"}]` |

各类型的值：

| type | 插件收到的值 | 保存时的检查 |
| --- | --- | --- |
| `string` | 字符串 | — |
| `secret` | 字符串，没填是 `null` | 存在**系统凭据管理器**（Windows 凭据管理器、macOS 钥匙串、Linux Secret Service）里，不进数据库、界面上不回显，只显示“已设置”。卸载时选“连设置一起删”才删除 |
| `bool` | `true` / `false` | — |
| `int` | 整数，没填是 `null` | 必须是整数 |
| `select` | 选中的 `value` | 必须是 `options` 里的值 |
| `folder` | 文件夹路径 | 文件夹必须存在 |

设置改了下次调用就生效。更新插件时设置保留。

## 10. 权限、信任级别和安装

### 权限

| 权限 | 作用 |
| --- | --- |
| `hosts` | rule / js：只能访问这些网站。所有入口：`resolve` 给出的下载地址必须在这里面。写法：`example.org`（只匹配它本身）、`*.example.org`（只匹配子域名，不含 `example.org` 本身，要两个都写）、`example.org:8080`（带端口时端口也要一致）；不写 `http://`、路径。本机 / 局域网地址（`192.168.1.10`、`nas.local`、`localhost`）要原样写出，安装确认页会特别标出来 |
| `login` | `optional` / `required`：插件想用用户在“网站登录”里**自己保存的**登录。安装时用户可以选择给不给（`required` 默认勾上），之后在插件详情的“权限”里随时打开或收回（只影响之后的调用）。rule / js 由软件自动带上 Cookie；process 从 `context.cookies` 拿 |
| `tools` | process：用软件自带的 yt-dlp / ffmpeg / ffprobe，路径在 `MP_YTDLP` 等环境变量里 |
| `paths` | process：声明要读写哪些文件夹（引用 `folder` 设置项），显示给用户看。process 是完全信任的程序，软件没法真正限制它 |

### 信任级别

- **受限（rule / js）**：在软件里运行，只能访问声明的网站，不能读写文件。确认页写“这个插件在软件的沙箱里运行”。
- **完全信任（process）**：在用户电脑上直接运行，能做任何普通程序能做的事。确认页醒目提示“这是一个程序插件”，用户必须勾选“我信任这个插件的来源”才能安装。

### 安装

安装方式：双击或拖入 `.mpx`、“设置 → 插件 → 已安装 → 安装插件…”选文件或文件夹、从仓库安装。确认页列出：名称、版本、作者、入口类型、下载源和类型、要访问的网站、登录、工具、README；已装过的显示当前版本，降级会标出来，比当前版本**多出来的权限**单独列出。

装好后：

1. 插件复制到 `<数据目录>\plugins\<id>\`，记下整个文件夹的摘要（所有文件的相对路径和内容一起算 SHA-256）；
2. 下载源加进“自动获取 → 我的来源”的“插件”分组（已经在的只更新名字，用户关掉过的保持关闭），`legacy_ids` 里的旧来源迁过来；
3. process 协议 2 的插件调一次 `info` 做自检，结果记在日志和状态里（失败不影响安装）。

### 文件摘要和重新确认

- 每次启动都重新算摘要。安装后插件文件夹里的文件被改过（不论是谁改的），插件被停用：“插件文件在安装后被改过，为了安全已停用”。重新安装，或用开发者模式加载即可。所以插件**不要往自己的文件夹里写东西**，用 `MP_PLUGIN_DATA`。
- plugin.json 要的权限超出用户同意过的（新网站、新工具、从 rule / js 变成 process）时，插件停用并提示重新安装确认。

### 停用、卸载、回退

- 停用：下载源从搜索中消失；用到它的下载任务开始时会失败，提示“插件已停用，启用后可以继续”，启用后重试即可。
- 卸载：移除下载源（连同追更）和随插件安装的规则，删除插件文件夹；可以选择连设置、密钥、`MP_PLUGIN_DATA` 一起删。
- 回到上一版本：更新后发现问题时用，见第 6 节。

## 11. 开发、测试和打包

### 开发者模式

“设置 → 插件 → 开发者 → 加载插件文件夹…”选你的插件文件夹：

- 直接用这个文件夹，不复制、不检查摘要；改了代码下次调用就生效，改了 plugin.json 也会自动重新读（新声明的权限直接生效，只限开发者模式）；
- 只支持 process 和 js 入口（rule 见第 5 节）；
- 同一个 id 已经正式安装时，要先卸载；
- 列表里标“开发者模式”，不参与自动更新。

### 测试面板

插件详情的“测试”页：选下载源、输入关键字，依次运行

1. **自检（info）**：只有 process 协议 2，显示 `info` 返回的 `message`；
2. **搜索**：显示结果条数和前 5 条的原始数据（有 `episodes` 能力时已经展开成各集）；
3. **解析下载地址（不下载）**：对第一条结果按默认档位调 `resolve`，显示下载方式；只有 `download` 能力的下载源不实际下载，提示去搜索页下一条试试。

每一步显示耗时、错误码和错误说明。

### 日志

插件详情的“日志”页，每个插件保留最近 300 条（重启软件清空），包括：

- 每次调用的结果（级别 `call`：“完成，用时 … 毫秒”，或 `error`）；
- process 的 `log` 事件、非 JSON 输出、标准错误最后 20 行（`stderr`）；
- js 的 `mp.log` / `console.*`；
- 安装、自动更新的记录。

### 命令行检查

`tools/mpplugin_check.py` 只用 Python 标准库：

```
python tools/mpplugin_check.py <插件文件夹或 .mpx> [--query 关键字] [--set key=value ...]
                               [--source 源 id] [--kind music] [--download] [--app-version 0.5.0]
```

- 检查 plugin.json（规则和软件一致）；
- process 协议 2：依次调 `info`、`search`、`episodes`（有的话）、`resolve`，检查返回格式、下载地址是否在 `hosts` 里、请求头、yt-dlp 格式；加 `--download` 时把第一条实际 `download` 到临时文件夹，检查 `files`；
- js / rule：只检查清单，运行请用软件里的测试面板。

例子：

```
python tools/mpplugin_check.py tools/plugin-examples/local-library --set library_dir=D:\Music --query 晴天 --download
```

### 打包

- 开发者模式里点“导出插件包”，会先检查再打成 `.mpx`；
- 或者自己压 zip 改扩展名。

## 12. 用 yt-dlp

两种方式：

1. **resolve 返回 `ytdlp` 目标**（推荐，rule / js / process 都能用）：

   ```json
   { "target": { "type": "ytdlp", "url": "https://example.org/watch/123", "format": "bv*[height<=1080]+ba/b" } }
   ```

   软件用自带的 yt-dlp 下载，参数由软件决定。插件**只能给页面地址和格式选择**（`-f` 的值）：`format` 不超过 120 个字符，不能以 `-` 开头，只能用字母、数字和 `*+/[]<>=!:._,-?^$|()`。不能加别的参数（`--exec`、`--cookies-from-browser`、下载器参数等都不行）。网址也必须在 `hosts` 里。用户选的档位 `key` 是数字时（如 `"720"`）还会当作画面高度上限。

2. **process 自己调用**：在 `permissions.tools` 里声明 `ytdlp`，从 `MP_YTDLP` 拿路径，在 `download` 里自己运行。这时插件是完全信任的程序，但请遵守同样的边界：不要用 `--cookies-from-browser` 读用户浏览器的 Cookie（要登录就用 `context.cookies`），不要用 `--exec` 之类执行别的命令。

## 13. 合规边界

这些是硬性规则，软件在能检查的地方都会检查：

- **不内置**：软件不带任何第三方网站插件，不内置、不推荐任何仓库地址。仓库由用户自己添加。
- **不替用户登录**：插件不能自己登录、不能要用户在插件设置里填网站密码。需要登录的网站，让用户在“网站登录”里自己登录，插件经用户同意后使用保存下来的登录；用户随时可以收回。
- **插件不能设置 Cookie**：js 的 `mp.http` 和所有下载目标的 `headers` 都不允许 `Cookie`；Cookie 只来自用户自己保存的登录。
- **不过验证码**：遇到验证码返回 `captcha`，让用户自己处理。不要接打码平台、不要自动识别验证码。
- **不绕过 DRM、付费、会员或地区限制**：不解密受保护的内容，不伪造会员身份，不用泄露的密钥或接口。
- **只访问声明的网站**：下载地址必须在 `hosts` 里；rule / js 的每个请求都检查。
- **yt-dlp 只给地址和格式**，见第 12 节。
- **只接有权获取的内容**：官方开放接口、自己的服务、已购买且允许下载的内容、公有领域 / CC 授权资源。

## 14. 常见问题

**装上后“我的来源”里没有？**
看“设置 → 插件 → 已安装”里这个插件有没有标出问题（清单不对、文件被改过、权限变了要重新确认）；插件是否启用；下载源在“我的来源”里是否被关掉了。

**搜索时这个来源没出现在结果里？**
搜索页当前类型不在下载源的 `media_kinds` 里时不会调用它；看搜索页“搜索范围”是否把它排除了；看来源计数旁边的错误提示。

**提示“先在插件设置里填写……”**
有 `required` 的设置没填，到插件详情“概况与设置”里填。

**process 插件报“启动插件失败（python）”**
用户电脑的 PATH 里没有这个程序。macOS / Linux 一般只有 `python3`，在 `runtime.command` 里按系统写；或者打成 exe。

**“插件没有输出 result 或 error 事件”**
结果没用 `{"event": "result", "data": …}` 输出；或者输出没换行 / 没 flush 就退出了；或者用了 `print(json.dumps(...))` 但是数据里有换行（`json.dumps` 默认不会产生换行，自己拼字符串时注意）。

**“插件的 search 超过 60 秒没有结束”**
网站太慢或程序卡在读标准输入：要读完标准输入（读到 EOF）再干活，软件写完请求就关闭标准输入。

**“第 N 条结果格式不对”**
多半是字符串字段写了 `null`，或者 `year`、`track` 写成了字符串。用 `tools/mpplugin_check.py` 跑一遍会指出是哪个字段。

**“下载地址的网站 … 不在插件声明的网站里”**
`resolve` 给出的地址（包括 CDN 域名）要写进 `permissions.hosts`。CDN 子域名多时写 `*.cdn.example.org`。注意 `*.example.org` 不匹配 `example.org` 本身。

**js 插件报“插件不能设置请求头 …”**
`mp.http` 只允许 `Referer`、`Accept`、`Accept-Language`。需要令牌的接口请改用 process 入口（令牌放在 `secret` 设置里），或让网站支持用户自己的登录。

**js 插件报“插件的 Promise 一直没有完成”**
沙箱里没有定时器，`await new Promise(r => setTimeout(r, 1000))` 这类写法永远不会完成。`mp.http` 是同步的，直接调用即可；同一网站的请求间隔由软件控制。

**改了插件文件后插件被停用了**
正式安装的插件不能改文件，见第 10 节。开发时用开发者模式。

**更新后出问题**
插件详情里“回到上一版本”。

**需要登录的网站一直报 `login_required`**
检查：plugin.json 写了 `login`；插件详情“权限”里“使用‘网站登录’里保存的登录”已打开；用户在“网站登录”里登录的就是 `hosts` 里的那个域名（process 的 `context.cookies` 只给没有 `*.` 的域名）。
