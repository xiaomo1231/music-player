# 漫画、小说、番剧来源接口开发说明

番剧、漫画、小说的“在线来源”和音乐共用同一套**下载源接口**（`src-tauri/src/fetch/provider.rs`，基础用法见 [下载源接口.md](下载源接口.md)），另外新增一套**资料源接口**（`src-tauri/src/meta.rs`），用来查作品的封面、简介和分集。

两套接口的注册表默认都是空的，软件不带任何来源。界面已经做好：接入第一个来源后，不用改前端、数据库或命令注册就能直接搜索、下载、追更、入库。

不改软件代码也能接下载源：写成插件（.em 规则、js 沙箱脚本或外部程序），番剧可以列分集、漫画按话给图片、小说按章给正文，见 [插件开发.md](插件开发.md)。

> 只接你有权获取内容的服务：官方开放接口（如 Bangumi、TMDB 的公开 API）、自己的 Jellyfin / Emby / Komga / Calibre-Web、已购买且允许下载的内容、作者免费公开的作品、公有领域书库。不接未授权转载站，不绕过付费、会员、口令或其他访问限制。

---

## 1. 两种接口分别管什么

| | 下载源 `Provider` | 资料源 `MetaProvider` |
| --- | --- | --- |
| 文件 | `src-tauri/src/fetch/provider.rs` | `src-tauri/src/meta.rs` |
| 回答的问题 | “去哪里下载” | “这是什么作品” |
| 方法 | `info` / `search` / `resolve` | `info` / `search` / `episodes` |
| 用户要不要添加 | 要，在“我的来源 → 可添加的下载源”点一下 | 不用，接入后自动生效 |
| 界面 | 搜索结果、下载列表、追更 | 搜索结果上方的作品资料卡 |
| 例子 | 自建 Jellyfin、OPDS 书库、正版平台的开放下载接口 | Bangumi、TMDB |

## 2. 整体流程

```
搜索页选“番剧 / 漫画 / 小说”，输入名字
  ├─ meta::search ──> 每个支持该类型的 MetaProvider::search ──> 资料卡（封面、简介、共几集、评分）
  │     “查看分集” ──> MetaProvider::episodes
  └─ fetch::search ──> Provider::search_works(query, media_kind, page) ──> Vec<Item>（有分集能力时只取作品，Hit.expand = true）
        Item ──> Hit（work = series，episode = episode），按“来源 + 作品”折叠成作品卡
        点开作品卡 ──> fetch_episodes ──> Provider::episodes(作品) ──> 各集（按集数排好）
用户点“下载这一个 / 全部下载 / 下载选中”，或“追更”
  └─ 下载队列 ──> Provider::resolve(item, quality) ──> Target
        Http      ──> 直链下载（断点续传）
        Ytdlp     ──> yt-dlp（含 m3u8 等流媒体）
        Magnet    ──> BT（librqbit，下完即停或做种）
        Pages     ──> 逐页下载图片到 pages-<任务号>\ ──> 打包成 CBZ
        Chapters  ──> 生成 EPUB
  └─ 整理入库（fetch/organize.rs）
        番剧  番剧\作品名\Season 01\作品名 - S01E03.ext
        漫画  漫画\作品名\作品名 第03话.cbz
        小说  小说\书名 - 作者.epub
        入库后番剧库、漫画、小说页直接能看
追更：每 30 分钟用同一个下载源重新搜一次作品名，带集数、之前没见过的条目自动加入下载
```

## 3. 下载源：番剧 / 漫画 / 小说要填的字段

`ProviderInfo.media_kinds` 写上支持的类型：`anime`、`manga`、`novel`（也可以和 `music`、`video` 并存）。搜索页选了不支持的类型时不会调用 `search`。

`Item` 里和这部分相关的字段：

| 字段 | 番剧 | 漫画 | 小说 |
| --- | --- | --- | --- |
| `title` | 单集标题，如“邮差与星” | 单话标题，如“第3话 星落之夜” | 书名或分卷名 |
| `series` | 作品名（**必填**，分组、追更、入库都靠它） | 作品名（必填） | 书名（可不填，不填用 `title`） |
| `season` | 第几季，可选 | 不用 | 不用 |
| `episode` | 第几集，可带小数（如 12.5） | 第几话 | 第几章（整本下载时不填） |
| `artist` | 字幕组 / 发布者，可选 | 作者 | 作者 |
| `media_kind` | `anime` | `manga` | `novel` |
| `qualities` | 清晰度，如 `1080P` / `720P` | 版本，如“高清 / 标清”“彩色版” | 一般只有一个，可留空 |
| `id` | **同一集要稳定不变**，追更靠“下载源 id + Item.id”判断是否下过 | 同左 | 同左 |

下载到的文件名由 `provider::file_name` 决定，整理入库会从文件名认回作品和集数：

| 类型 | 文件名 |
| --- | --- |
| 番剧 | `星屑邮局 - 03.mkv`，第 2 季起 `星屑邮局 S02E03.mkv` |
| 漫画 | 有 `episode`：`星屑邮局 第03话.cbz`；没有：`星屑邮局 第2卷.cbz`（`series + title`） |
| 小说 | `潮汐档案 - 林间.epub`（书名 - 作者） |

## 4. 下载源：`resolve` 返回什么

```rust
pub enum Target {
    Http { url: String, ext: String },
    Ytdlp { url: String },
    Magnet { uri: String },
    Pages { urls: Vec<String>, headers: BTreeMap<String, String> },
    Chapters { chapters: Vec<TextChapter> },
}
pub struct TextChapter { pub title: String, pub text: String }
```

按来源的形态选一种：

| 来源给的是 | 用 | 说明 |
| --- | --- | --- |
| 整个视频文件 / 整本 CBZ、EPUB、PDF 的直链 | `Http` | `ext` 写 `mkv` / `cbz` / `epub` / `pdf` |
| 网页播放页、m3u8 | `Ytdlp` | 需要用户装了 yt-dlp |
| 磁力或种子 | `Magnet` | 用户设置里的做种策略照常生效 |
| 漫画一话的图片地址列表 | `Pages` | 按顺序下载，自动识别 png / jpg / webp / gif / avif；`headers` 放 Referer、授权令牌等。每页失败重试 3 次，暂停后继续会跳过已下好的页 |
| 小说正文 | `Chapters` | `text` 是纯文本，一行一段；生成 EPUB 3（带目录），小说页直接打开 |

`resolve` 每次开始或继续下载都会被调用，图片地址、直链过期也没关系。`Chapters` 会一次性生成整本，章节多时建议在 `resolve` 里自己限速（`source::throttle`）。

### 示例：漫画下载源骨架

网址和字段是假设的，按真实服务的开放接口文档改。

```rust
use super::provider::{Item, Provider, ProviderInfo, Resolved, Target};
use super::source;
use futures_util::future::BoxFuture;
use std::collections::BTreeMap;

#[derive(Default)]
pub struct DemoComics;

const API: &str = "https://api.example.org/v1";

impl Provider for DemoComics {
    fn info(&self) -> ProviderInfo {
        ProviderInfo {
            id: "demo-comics".into(),
            name: "示例漫画库".into(),
            media_kinds: vec!["manga".into()],
            note: "官方开放接口，只含免费章节".into(),
        }
    }

    fn search<'a>(&'a self, query: &'a str, _mk: &'a str, _page: u32) -> BoxFuture<'a, Result<Vec<Item>, String>> {
        Box::pin(async move {
            let url = format!("{API}/search?q={}", url::form_urlencoded::byte_serialize(query.as_bytes()).collect::<String>());
            let v: serde_json::Value = serde_json::from_slice(&source::http_bytes(&url).await?).map_err(|e| e.to_string())?;
            let mut out = vec![];
            for work in v["works"].as_array().into_iter().flatten() {
                for ch in work["chapters"].as_array().into_iter().flatten() {
                    out.push(Item {
                        id: ch["id"].as_str().unwrap_or_default().into(),
                        title: ch["title"].as_str().unwrap_or_default().into(),
                        series: work["title"].as_str().unwrap_or_default().into(),
                        artist: work["author"].as_str().unwrap_or_default().into(),
                        episode: ch["number"].as_f64(),
                        cover: work["cover"].as_str().unwrap_or_default().into(),
                        media_kind: "manga".into(),
                        ..Default::default()
                    });
                }
            }
            Ok(out)
        })
    }

    fn resolve<'a>(&'a self, item: &'a Item, _q: &'a str) -> BoxFuture<'a, Result<Resolved, String>> {
        Box::pin(async move {
            let url = format!("{API}/chapters/{}/pages", item.id);
            let v: serde_json::Value = serde_json::from_slice(&source::http_bytes(&url).await?).map_err(|e| e.to_string())?;
            let urls = v["pages"].as_array().into_iter().flatten().filter_map(|p| p.as_str().map(String::from)).collect();
            Ok(Resolved {
                target: Target::Pages { urls, headers: BTreeMap::from([("Referer".into(), "https://example.org/".into())]) },
                lyric: None,
            })
        })
    }
}
```

番剧来源 `resolve` 返回 `Target::Http { url, ext: "mkv".into() }` 或 `Target::Magnet { uri }`；小说来源返回 `Target::Chapters { chapters }`。

接入步骤和音乐一样：`fetch.rs` 加 `pub mod <名字>;`，`provider.rs` 的 `builtin()` 里加一行，写测试。

## 5. 资料源接口

```rust
pub trait MetaProvider: Send + Sync {
    fn info(&self) -> MetaInfo;
    fn search<'a>(&'a self, query: &'a str, media_kind: &'a str) -> BoxFuture<'a, Result<Vec<Subject>, String>>;
    fn episodes<'a>(&'a self, subject_id: &'a str) -> BoxFuture<'a, Result<Vec<EpisodeMeta>, String>>;
}
```

| 结构 | 主要字段 |
| --- | --- |
| `MetaInfo` | `id`、`name`、`media_kinds`、`note`、`link_template`（作品页网址模板，`{id}` 换成作品 id，如 `https://bgm.tv/subject/{id}`） |
| `Subject` | `id`、`title`（原名）、`title_cn`、`aliases`、`media_kind`、`year`、`date`、`cover`、`summary`、`total`（总集 / 话数）、`rating`（0–10）、`tags`、`staff`、`extra` |
| `EpisodeMeta` | `sort`（第几集，对应文件名里的集数）、`title`、`title_cn`、`airdate`、`duration`（秒）、`special` |

接入：新建 `src-tauri/src/meta/<名字>.rs` 或直接放在 `meta.rs` 旁，实现 trait，在 `meta.rs` 的 `builtin()` 里加一行。`search` 按匹配度排序，第一项默认显示在资料卡上；用户点“不是这部”会轮换到下一项（每个资料源最多取 3 项）。

以 Bangumi 为例，对应的公开接口：

| 方法 | Bangumi 接口 |
| --- | --- |
| `search` | `POST https://api.bgm.tv/v0/search/subjects`，`filter.type`：动画 2、书籍 1 |
| `episodes` | `GET https://api.bgm.tv/v0/episodes?subject_id=<id>` |
| 每日放送（以后做追番日历用） | `GET https://api.bgm.tv/calendar` |

Bangumi 要求请求带能识别应用的 User-Agent，`source::client()` 已经带了。需要登录的功能（收藏、看到第几集）要 Access Token，存法见 [下载源接口.md](下载源接口.md) 第 4 节。

前端命令：

| 命令 | 参数 | 返回 |
| --- | --- | --- |
| `meta_providers` | 无 | `MetaInfo[]` |
| `meta_search` | `query`、`mediaKind` | `{ cards: [{ provider, provider_name, link, subject }], notes }`；没有资料源时 `cards` 为空 |
| `meta_episodes` | `provider`、`subjectId` | `EpisodeMeta[]` |

## 6. 界面上已经做好的部分

全部在“自动获取”页，没有接入来源时不显示多余的东西：

- **搜索并下载**（`src/components/fetch/Search.svelte`）
  - 类型切换增加“漫画”“小说”。选了漫画或小说但没有支持的下载源时，提示“接入后会出现在左边可添加的下载源里”。
  - 有资料源时，结果上方显示资料卡：封面、中文名 / 原名、年份、共几集 / 话 / 章、评分、作者、简介；“查看分集”展开分集标题和放送日期；“作品页”打开资料源网页；“不是这部”换下一个候选。
  - 下载源结果每行显示“作品 · 第几集 / 话 / 章 · 作者 / 字幕组 · 年份”，多个版本时可以下拉选择。
  - 下载源的结果按“来源 + 作品”折叠成作品卡（封面、作品名、来源、共几话、最新话），多列排布；点开才取章节，可以全选、按区间（第 1–50 话）勾选、只选未下载、正序 / 倒序，每次显示 60 话，“下载选中”批量下载。磁力 / RSS 等多个版本的结果仍逐条列出。
  - 作品卡上“追更”会记下这部作品和封面：漫画 / 小说 / 番剧书架里这部作品的详情页显示“追更中”和“检查更新”（有新的就加入下载，没有就提示“没有更新内容”）；书架上还没有这部作品时，在书架顶部“追更中”一栏显示。
- **我的来源**（`Sources.svelte`）：“可添加的下载源”悬停显示说明和支持的类型；有资料源时列出资料源和支持的类型。
- **下载列表**（`Downloads.svelte`）：放在页面右上角的“下载”按钮里（按钮显示进行中数量和总进度），点开从右侧滑出；每个任务标出类型（番剧 / 漫画 / 小说……），漫画按页下载时进度按页数走。

## 7. 测试

不联网的假实现可以照着写：

- `fetch/provider.rs` 的 `tests::Mock`（下载源）
- `meta.rs` 的 `tests::MockMeta`（资料源）

已有测试：

| 命令 | 覆盖 |
| --- | --- |
| `cargo test --lib provider` | 番剧 / 漫画 / 小说文件名、`Hit` 带上作品和集数、旧任务地址兼容、`Target` 的 JSON 格式 |
| `cargo test --lib pack` | 图片格式识别、CBZ 按页序打包、生成的 EPUB 能被小说阅读器读回 |
| `cargo test --lib meta` | 资料源按类型筛选、每源条数上限、出错提示、分集 |
| `cargo test --lib fetch::organize` | 漫画 / 小说整理路径；下载任务是漫画时普通 zip 也按漫画整理 |
| `cargo test --lib fetch::tests::seen_key` | 追更判断“已下过”用 `下载源 id + Item.id`，封面等字段变化不会重复下载 |

接入真实来源后，用独立数据目录（见 `开发约定.md`）各下一集 / 一话 / 一本，确认整理后的路径、番剧库 / 漫画 / 小说页能打开、追更能抓到新集。

## 8. 现在没做的

- 搜索只取第 1 页。
- 资料源只用于显示，还没有在整理入库时自动补封面、简介和集标题，也没有同步观看进度（Bangumi 收藏）。
- 小说只支持一次生成整本 EPUB，不支持追加新章节到已有的书；追更时每次新章节会生成单独的文件。
- 资料源只支持编译进软件的；下载源可以用插件接入，见 [插件开发.md](插件开发.md)。
