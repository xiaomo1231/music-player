# 规则文件（.em）

.em 是用户自己添加的**声明式规则文件**：软件按规则做固定的几种事（漫画排版、小说排版、整理文件、接入下载源），规则本身不能运行程序。

> 软件不内置、不推荐任何第三方网站的规则。只导入你信任、且来源有权获取内容的规则。规则不能自己登录、过验证码，也没有加解密函数，做不了绕过付费或 DRM 的事。需要写算法的来源请用[外部程序下载源](下载源接口.md#9-外部程序下载源自己写的-exe)。

## 1. 文件格式

UTF-8 文本，内容用 YAML 写（纯 JSON 也能直接读）。文件不超过 256 KB。所有规则都有这几个头部字段：

| 字段 | 说明 |
| --- | --- |
| `em` | 格式版本，现在是 `1`。比软件支持的高时提示更新软件 |
| `kind` | `comic` 漫画排版 / `source` 下载源 / `clean` 小说排版 / `organize` 整理文件 |
| `id` | 小写字母、数字、`-`，2~40 个字符。同 id 再导入就是更新，**发布后不要改** |
| `name` | 显示名 |
| `version` / `author` / `note` | 可选，显示用 |
| `hosts` | 只有 `source` 用：允许访问的域名，如 `archive.org`、`*.example.org`、`nas.local:8080` |
| `login` | 只有 `source` 用：`none` / `optional` / `required`，是否带上用户在“网站登录”里自己登录保存的 Cookie |

各类规则的正文见：

- [漫画排版 comic](rules/comic.md)
- [下载源 source](rules/source.md)
- [小说排版 clean](rules/clean.md)
- [整理文件 organize](rules/organize.md)

示例在 [`tools/em-examples/`](../tools/em-examples/)。

## 2. 导入和管理

- 三种导入方式：双击 .em 文件（安装包注册了文件关联）、拖进窗口、设置 → 规则文件 → “导入…”。
- 导入前弹出确认框：名称、版本、作者、规则会做什么、要访问哪些网站（本机 / 局域网地址和比旧版本新增的网站会标出来）。有错误时列出行号，不能导入。
- 导入后文件复制到 `<数据目录>\rules\<id>.em`。“编辑”用系统默认程序打开这个文件，保存后下次使用时自动重新读取；如果改动后多了要访问的网站，规则会停用并提示重新导入确认。
- 每个规则可以启用 / 停用、测试、导出、删除。

## 3. 实现

| 位置 | 内容 |
| --- | --- |
| `src-tauri/src/em/format.rs` | 读文件、头部检查、hosts 检查、版本比较 |
| `src-tauri/src/em/mod.rs` | 表 `em_rules`、规则目录、内存注册表（文件改了自动重读）、命令 `em_inspect` / `em_install` / `em_list` / `em_set_enabled` / `em_delete` / `em_export` / `em_open` / `em_test`，事件 `em://changed` |
| `src-tauri/src/em/{comic,source,clean,organize}.rs` | 各类规则的检查（`check`）、生效 / 失效（`apply`）、删除清理（`removed`）、测试（`test`） |
| `src/lib/em.svelte.ts` | 前端类型和命令 |
| `src/components/em/RulesCard.svelte` | 设置页的规则管理卡片 |
| `src/components/em/ImportModal.svelte` | 导入确认框 |
| `src/components/em/test/*.svelte` | 各类规则的测试面板 |

新增一类规则：在 `format::Kind` 里加一项，新建 `em/<kind>.rs` 实现上面四个函数，在 `mod.rs` 的分发里各加一行。
